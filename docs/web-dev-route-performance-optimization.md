# Web 开发环境路由切换性能优化开发文档

## 目标

缩短局域网开发服务器中首页、账户页等 tab 页面首次访问和切换时的等待，移除与当前路由无关的重量级模块编译和加载开销。

## 已确认现象

- `next dev --webpack` 首次访问账户页发生约 21.8 秒按需编译。
- 开发服务热态下，本机直连首页约 307–320ms、账户页约 338–376ms；并发请求时接近 1 秒。
- 同一份静态导出产物在本机热态约 10–13ms，说明不是业务数据、本地数据库、后端 API 或局域网造成。
- tab 共享布局静态引入记账面板，记账面板又静态引入储蓄规划器；账户页静态引入 Excel 解析依赖。

## 实施步骤

- [x] 建立开发服务和静态产物的路由响应对照测量。
- [x] 将开发服务器改为 Turbopack，并配置项目根目录以覆盖 pnpm 依赖链接。
- [x] 将 Excel 账单解析库改为文件选择时按需加载。
- [x] 将储蓄规划器改为仅在打开储蓄面板时加载，同时保持普通工资记账即时打开。
- [x] 在临时开发端口测量优化后首页和账户页首访/热态响应。
- [x] 运行测试、类型检查、生产构建，更新版本记录并完成本地 Git 提交。

## 验收标准

1. 开发命令不再强制使用 webpack。
2. 首页与账户页不会静态打入 `xlsx`、储蓄规划器及其依赖。
3. 账户页仅在选择 CSV/XLS/XLSX 文件后才加载 Excel 解析模块。
4. 首页工资入口仍在已加载的记账面板中立即显示。
5. 优化后的临时开发服务路由首次编译与热态响应可量化地优于原服务。
6. 静态导出构建和既有测试保持通过。

## 验证结果

- 临时 Turbopack 服务：首次访问首页约 `2.8s`，后续首页请求约 `35–40ms`；首次账户页编译约 `747ms`，后续账户页请求约 `62–69ms`。
- 6 个并发账户页请求平均约 `345ms`，相较旧 Webpack 服务约 `986ms` 降低约 65%。
- 已通过 `pnpm test`（66 项）、`pnpm run typecheck` 和 `pnpm build`。
- 测速使用的临时服务与副本均已关闭、删除；未影响正在使用的 `12366` 服务。

## 二次优化（首次编译等待）

### 新现象

- 新服务仍会在每个 tab 路由的第一次访问时执行 Turbopack 编译；消费页约 `9s`、首页约 `2.6s`、储蓄页约 `2s`。
- 后续同一路由请求为 `26–63ms`，因此问题是开发模式冷路由编译，而不是页面切换后的业务数据读取。

### 实施步骤

- [x] 用用户日志复现并区分冷编译与热态请求。
- [x] 确认消费页静态导入图表构建组件、储蓄页静态导入完整编辑器是首访模块图的额外开销。
- [x] 将消费页图表改为页面绘制后按需加载，并保留加载占位。
- [x] 将储蓄类型文案移出完整编辑器，使储蓄总览不再依赖编辑模块。
- [x] 开发服务启动后后台预热全部 tab 路由，避免用户第一次点击时触发编译。
- [x] 在隔离服务中重新测量冷启动、预热完成后的路由访问，并运行回归校验。

### 二次验证结果

- 后台预热时的冷编译：首页约 `2.6s`、消费页约 `2.7s`、储蓄页约 `1.4s`；等待发生在服务刚启动后的后台，不占用用户点击某个 tab 的时机。
- 收到 `Tab routes prewarmed.` 日志后，服务内部路由请求为：首页 `43ms`、消费 `46ms`、储蓄 `44ms`、贷款 `48ms`、资产 `54ms`、账户 `57ms`。
- 预热完成后的外部 HTTP 测量约 `62–102ms`。
- 已再次通过 `pnpm test`（66 项）、`pnpm run typecheck` 与 `pnpm build`。
