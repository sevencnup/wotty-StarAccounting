# 主标签页返回策略开发文档

## 目标

- 底部主标签页（首页、消费、储蓄、贷款、资产、设置）之间切换时，不再逐个写入浏览器历史记录。
- Android WebView 的边缘侧滑与浏览器返回仍优先交给已打开的分层弹层；没有弹层时，不再在主标签页之间来回切换。
- 保留独立路由页面、详情页和表单的正常返回语义，以及长时间后台恢复后的导航自愈逻辑。
- 即使 WebView 中残留旧版标签页历史，Android 原生返回也不能绕过上述规则。
- 浏览器、旧版 Android WebView 或原生返回实现直接触发 `popstate` 时，也必须阻止主标签之间的回退。

## 实施步骤

1. 将底部主导航的正常客户端跳转改为替换当前历史记录，而不是默认追加记录。
2. 保持后台恢复后的硬重载分支，确保失活的 Android WebView 仍直接重建用户选中的标签页。
3. 在共享标签布局中增加捕获阶段的 `popstate` 兜底：只有“当前、目标均为主标签且无打开层”时，立即前进回当前标签并阻断 Next 路由处理旧标签。
4. 统一记录分层历史 Hook 的活动状态，保证日期选择器、表单和底部抽屉仍优先消耗自己的返回记录。
5. 为 Android 原生返回增加 WebView 历史判断：带 `stark` 分层标记的 URL 与二级路由继续回退；当前为主标签且上一项仍属同源应用历史时，交给系统默认返回而不切换旧标签。
6. 为原生返回和前端导航规划补充单元测试，明确普通标签切换采用替换策略。
7. 更新未发布版本记录，执行前端类型检查、测试、生产构建及 Android 单元测试，并提交本地 Git 仓库。

## 验收标准

- 从首页依次点击消费、储蓄、资产后，侧滑返回不会依次回到储蓄和消费。
- 含有更新前遗留主标签历史的已运行 WebView，也不会因侧滑切换到旧标签页。
- 在浏览器和未更新原生壳的开发连接中，直接触发的 WebView 回退也会留在当前主标签。
- 打开日期选择器、表单、筛选或其他弹层时，侧滑仍只关闭最上层 UI。
- `/app/journal`、`/app/budgets` 等独立路由仍可按既有路由历史返回。
- 应用从后台长时间恢复后，第一次点击底部标签仍能正常进入目标页面。
