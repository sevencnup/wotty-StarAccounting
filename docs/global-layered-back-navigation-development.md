# 全局分层返回开发文档

## 目标

- 在 Android WebView、移动浏览器的边缘侧滑返回和浏览器返回操作中，每次仅关闭当前最上层可关闭 UI。
- 覆盖底部抽屉、全屏新增/编辑表单、日期与月份选择器、确认框、弹窗和筛选浮层。
- 保持路由型页面的既有返回语义，不把正常路由返回误处理成关闭弹层。

## 实施步骤

1. 统一现有的历史标记 Hook，使每个临时 UI 层在打开时保留父层状态并写入独立历史记录；手动关闭时仅消费自身记录，系统返回时只回调自身关闭逻辑。
2. 将 `BottomSheet` 改用统一 Hook，保留动画期间的点击屏蔽和 `historyMode="route"` 的路由型抽屉行为。
3. 为 `JournalPanel` 增加可配置的历史模式：由标签页或路由管理历史时不重复写入；其他新增、编辑、记录表单自行登记为一层。
4. 将首页薪资设置、设置页退出确认、消费页筛选浮层、储蓄历史模板选择等非通用组件接入同一返回层机制；切换同组筛选时复用同一层，不遗留空历史记录。
5. 为历史标记的层级返回和手动关闭补充单元测试，并执行类型检查、全量测试、生产构建和差异检查。
6. 更新未发布版本记录，并提交本地 Git 仓库；不推送 GitHub。

## 验收标准

- 在“添加储蓄 → 日期选择”中，第一次侧滑只关闭日期选择器，第二次才关闭添加页。
- 在“编辑/新增表单 → 选择器/模板”中，所有内层 UI 先关闭，父表单保持原样。
- 在首页、设置、消费页打开的弹层或浮层中，侧滑每次只关闭一层。
- 手动点击取消、关闭、遮罩、确定或选择选项后，不会遗留需要额外侧滑才能恢复页面的空历史记录。
- `/app/journal`、`/app/budgets` 等路由型页面仍按原路由历史返回。
