# 各页面云端数据本地缓存

## 问题

Web 壳和 KT 混合版切换页面、重开应用时，多个页面会重新等待云端账单和业务数据，整页骨架屏停留时间过长。现有云端缓存只保存在内存，无法跨 WebView 重建复用。

## 实施步骤

1. 在共享云端数据仓库增加按 API 地址、登录用户和资源键隔离的 IndexedDB 缓存。
2. 页面读取数据时优先返回本地缓存，并在后台请求云端；数据变化后通知正在显示的页面更新。
3. 写入、导入和删除成功后清除对应缓存，避免新记账后读到旧结果。
4. 缩短首页串行等待，业务模块和账单月份并发加载。
5. 混合版空闲后预加载主标签路由资源，减少首次切页等待。
6. 递增内部测试包版本，构建 KT 混合版并安装到已连接手机。

## 验收

- 第二次进入主要页面或重开应用时，可先显示同一账户的本地数据。
- 网络恢复后页面更新到云端数据；切换用户、账本或 API 时不会串用缓存。
- 新增、修改和删除账单后，相关页面不继续显示旧缓存。
- 旧 APK 归档文件保持不变，新 APK 使用独立文件名。
