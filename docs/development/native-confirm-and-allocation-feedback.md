# 统一删除确认弹窗并修正资金分配反馈

## 问题与目标

多个删除入口使用浏览器原生 `window.confirm`，在浏览器和 Android WebView 中会显示系统弹窗，视觉与应用不一致。首页资金分配卡片的消费金额和进度条在新增消费后没有给出符合直觉的反馈，需要核对数据刷新、发薪周期范围和进度比例。

## 定位结果

- 云端写入在请求发出前清理流水缓存；请求进行中如果首页读取了旧数据，旧数据会重新进入缓存。写入成功后的刷新仍可能读取这份旧缓存。
- 进度条以本期收入为基数。截图中的 ¥18.80 / ¥7,062.67 约为 0.27%，原来的色段在窄屏上几乎不可见。
- 首页消费金额只统计当前发薪周期内的流水；周期外的消费仍显示在对应日期的消费记录中。

## 实施步骤

1. 找齐应用源码中的原生提示调用，建立统一的应用内确认弹窗，支持取消、确认、遮罩、返回键和键盘操作。
2. 将所有原生删除确认入口改用同一组件，保留原有文案和删除行为。
3. 追踪记账保存到首页汇总的刷新链，核对发薪周期边界、消费类型与进度条比例；修正发现的问题，并让金额和可视进度表达一致。
4. 静态复核调用与数据口径，更新版本记录；本次不增加或运行测试。
5. 只提交本次文件到本地 Git，不推送 GitHub。

## 验收重点

- 全部删除确认均显示应用内样式，取消或返回不会执行删除，连续操作不会让弹窗卡住。
- 本期内新增、修改、删除消费后，首页消费金额、实际收支净额和进度条保持同步。
- 发薪周期外的消费不会混入当前周期，页面能清楚说明统计范围。
