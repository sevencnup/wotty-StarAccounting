# 纯 Kotlin 薪资单月与历史批量补录

## 目标

对照 Web 原生记账页 `app/src/components/stark/JournalPanel.tsx` 和 `app/src/lib/stark/journal/salary-batch.ts`，在纯 Kotlin 全局记账入口补齐明确的工资录入模式与历史批量补录。工资流水写入当前本地或云端账本；重试不能生成重复月份记录，保存后首页、预算、流水和消费汇总要同步更新。

## 当前差异

- Web 记账入口有“普通记账 / 添加薪资收入”，工资还可选单月录入或批量补录。
- 批量补录支持年份、多个月份、每月金额、发薪日、入账账户和发薪单位；已有工资月份会跳过。
- Web 对工资月份的判断会检查 `INCOME` 类型及分类、商户、说明中的“工资/薪资/薪酬”；发薪日限制在 1–28 日，流水时间为当日 09:00。
- Web 工资流水的订单号为 `salary-batch:YYYY-MM`，说明为“历史工资补录”，状态为“已补录”。
- 原生快速记账已支持支出、收入、转账、分类、平台、商户、日期时间、备注、编辑和删除；目前没有单独的工资模式和批量补录。原生 `NativeApiClient` 已提供云端批量导入接口，且本地实体库支持批次写入。

## 实施步骤

1. 新增流水时提供“普通记账 / 工资收入”入口；编辑既有流水时保留原类型和字段，不显示模式切换。
2. 工资入口默认 `INCOME` / “工资”，提供“单月录入 / 批量补录”。单月工资复用现有金额、分类、账户、日期、商户和备注表单。
3. 批量表单提供年份（2000–9999）、1–12 月多选、全选/清空、每月金额、发薪日（1–28）、入账账户和发薪单位。
4. 按 Web 规则整理并去重月份；用工资分类/商户/说明判断当前账本已录入月份。已有月份明确跳过，不产生第二笔工资。
5. 对待录入月份构建完整流水字段：`INCOME`、分类“工资”、平台、商户（空值时“工资补录”）、09:00 发薪时间、订单号 `salary-batch:YYYY-MM`、说明“历史工资补录”、状态“已补录”，以及当前用户/账本字段。
6. 为每个账本和月份生成稳定流水 ID，并同时按流水 ID、订单号防重。LOCAL 在 SQLite 批次事务中写入；CLOUD 调用已有 `/api/transactions/import?accountId=...`，按服务器回传的导入、跳过、失败计数显示结果，不能在请求失败时先改页面或缓存。
7. 部分失败时保留选择和输入以便重试；成功和跳过结果留在表单中显示。更新本地流水和结余，云端成功后刷新当前账本；首页预算和消费统计使用同一份流水状态。
8. 真机以未来年份和低金额临时补录两个工资月份，核对日期、平台、商户、收入汇总和首页联动；再次提交同月份确认跳过；删除临时流水并确认首页恢复原值。再检查空月份、金额无效、日期边界、批量导入错误提示。云端写入只在可控开发账户下验收，不改真实账户。
9. 递增原生版本和 `versionCode`，记录验收与 `CHANGELOG.md`；构建安装独立调试包、检查 `git diff --check`，只提交源码、文档和版本文件到本地 Git，不推送 GitHub。
