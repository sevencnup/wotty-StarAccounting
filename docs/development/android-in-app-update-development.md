# Android 应用内下载与安装更新开发文档

## 目标

- Android Web 壳版和 KT 混合版从更新弹窗直接下载对应 APK，在应用内显示进度，下载完成后打开系统安装确认页。
- 处理 Android 8 及以上版本的“允许安装未知应用”授权；返回应用后继续安装。
- 下载失败、安装授权被拒和用户关闭安装器后均可重试，不再依赖外部浏览器。

## 当前实现与约束

- 更新入口位于 `AppUpdatePrompt.tsx`，目前用 `window.open` 打开 APK URL，因此会跳到浏览器。
- 两种 Android 版本共用 `MainActivity` 和同一个 React 更新弹窗；APK 必须与当前安装包的包名一致，且版本号更高。
- Android 已配置应用缓存目录的 `FileProvider`，但还没有 APK 下载插件和安装未知应用权限。
- 普通应用不能静默安装；下载完成后仍需用户在 Android 系统安装界面确认。
- 旧安装包不具备原生下载能力，必须先安装包含此功能的新包一次。

## 实施步骤

1. 在主 Activity 注册 Capacitor 更新插件；Manifest 声明安装 APK 所需权限。
2. 插件只接受 HTTPS 链接，在后台下载到应用缓存目录，报告下载进度，限制文件大小并清理失败的临时文件。
3. 下载后检查 APK 的包名和版本号；通过 `FileProvider` 授权系统安装器读取 APK。若缺少安装权限，打开对应系统设置并在返回后继续。
4. 更新弹窗接入插件，呈现下载、授权、错误和重试状态；保留现有版本检查与版本渠道判断。
5. 按新增功能更新版本号、Android `versionCode` 和版本记录；构建新的安装包并本地提交。若设备可连接，按既有偏好安装到手机。仅在用户明确要求时推送 GitHub。

## 验收要点

- 点击“下载更新”时不跳浏览器；界面显示实际下载进度。
- 正确 APK 可进入系统安装确认页；首次缺少授权时可从系统设置返回继续。
- 损坏 APK、错包、旧版本、下载失败时显示错误且可重试。
- Web 壳和 KT 混合版共用流程，原有网页端不显示 Android 更新弹窗。
