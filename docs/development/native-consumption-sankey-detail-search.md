# 纯 Kotlin 消费桑基图与流水二次搜索

## 目标

对齐 Web 消费分析页的账户到分类流向图和流水明细二次搜索。保留现有原生月份/全年、收支、账户、分类和主搜索筛选，不改写已完成的趋势、分类、节律和 CRUD。

## 已核对的 Web 规则

- 页面入口：`app/src/app/app/(tabs)/consumption/page.tsx`。
- 图表实现：`app/src/components/stark/ConsumptionCharts.tsx` 的 `buildSankeyOption`。
- 流向数据由当前主筛选结果聚合，按标准化支付账户和账单分类汇总金额；Web 以桑基图展示账户到分类的连接及金额权重。
- 流水明细搜索只在当前筛选结果内执行；显示匹配数量，并按时间倒序展示最近五笔，支持编辑和删除。
- 原生页已具有同样的主搜索和筛选，原流向卡展示最多十条文字连线，流水列表则展示全部结果且没有第二个独立搜索框。

1. 将原生流向卡改为 Compose Canvas 桑基图，按账户和分类汇总边权，显示金额比例连接；点账户或分类节点仍可切换相应筛选。
2. 在原生流水列表前加入限定于当前过滤结果的二次搜索；显示总匹配数和最近五条，保留编辑/删除入口。
3. 更新完整开发清单和原生版本记录。
4. 构建纯 Kotlin `.dev` 包并核对包名、版本和安装包留档。
5. 真机界面验收需在当前 Codex Remote 会话不被打断时进行；本轮仅做构建与静态差异核对。

## 验收范围

- 月份/全年、收支、账户、分类及主搜索变化后，趋势、流向图和二次搜索均基于同一筛选集合。
- 桑基图账户节点、分类节点和连接权重与同一过滤集合的金额汇总一致；无流水时展示清楚的空态。
- 点击账户或分类节点仍切换对应过滤条件，筛选可重复清除。
- 二次搜索匹配分类、账户、商户和备注，展示匹配数量及最近五笔。
- 最近流水仍可编辑、删除，且不影响其余筛选行为。
