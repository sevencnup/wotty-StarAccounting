# 演示储蓄计划入口与金额对账

## 问题与分类

- 首页“计划支出明细”来源于储蓄目标的月度计划表，但只提供储蓄总览链接，目标卡的“编辑目标”也没有说明其中包含月度计划和固定支出。
- 演示目标累计已存为 41,700 元，现有已完成计划仅为 10,200 元，缺少历史已存的对应记录。
- 宣传站独立储蓄模块还保留了旧的首付历史金额，与完整演示不一致。

本次属于修复（PATCH）：让现有月度计划入口可发现，并补齐演示金额来源；不增加新的记账任务。应用目标版本为 `0.7.4-dev.1`，Android 源码版本序号递增为 `158`；宣传站递增为 `0.5.2`。本次不构建安装包。

## 实施步骤

1. 读取现有计划、目标进度、首页汇总和框架静态导出说明。
2. 提取可单独验证的演示储蓄数据，补全三笔历史完成记录，并依据完成记录生成初始目标已存金额。
3. 为已有演示账本增加一次性历史记录迁移：仅在缺口与预设历史金额吻合时补缺失记录，不覆盖访客修改，不清空存储，也不影响非演示账本。
4. 首页计划汇总附上对应目标和月份的计划表链接；储蓄目标入口明确标为“目标与计划”。记录列表显示可见条数，超过八条时可展开全部记录，保持现有编辑和存入流程。
5. 同步宣传站储蓄示例的历史记录与待存计划，保持现有两屏布局。
6. 增加针对初始金额、迁移幂等、访客修改保护和月度计划来源的回归检查，执行类型检查。
7. 更新应用版本记录并本地提交源仓库；依次重建手机和完整 Web 演示，再验证宣传站构建、来源信息、页面与资源。
8. 恢复 Next.js 自动改写的类型声明，仅本地提交本任务文件，保留私人笔记、已有安装包与构建产物。分别报告远程推送和部署状态。

## 验收

- 三个目标已存金额分别等于各自已完成记录之和，总计 41,700 元。
- 待存、跳过的计划不增加已存金额；10 月已存仍为 7,000 元。
- 首次访问和已访问过的未修改演示账本均能显示完整记录，重复初始化不重复入账。
- 首页明细可打开正确目标的原有月度计划表，房租、水电等金额来自同一笔计划。
- 手机演示、独立 Web 演示和宣传站储蓄预览数据一致；不添加大边框或新的大型模块。
