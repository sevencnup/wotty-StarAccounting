# 纯 Kotlin 版视觉一致性开发记录

## 目标

缩小纯 Kotlin/Compose 版与网页版在字号、字重、卡片层级、间距和模块布局上的差距。网页版已经迭代到新的首页组件，而原生首页仍保留一套独立的 `WebReplica*` 实现；本轮先修复所有原生页面共享的阅读体验，再对齐首页核心卡片，并通过手机截图检查是否出现截断或拥挤。

## 已确认的差异

- 网页默认正文基准为 15px，原生版有大量直接写死的 8–13sp 小字号。
- 原生主题把默认字重设为 Normal，且使用固定 Normal 的 sans-serif 字体对象。
- 网页首页使用 `StarkCrystalHero` 和 `StarkBudgetAllocationCard`；原生首页仍使用 `WebReplicaHero` 和 `WebReplicaBudgetCard`，布局和视觉层级已经分叉。
- 网页卡片按模块使用不同圆角：新版预算卡片约 18px、余额卡片 20px、罗盘小卡 16px；原生这些圆角基本接近，但默认内边距偏紧、卡片阴影偏弱，首页模块间距也小于网页。
- 储蓄页的 `Scaffold` 已经应用系统状态栏内边距，页面标题又重复应用一次，导致标题和首个模块整体下沉。

## 本轮执行步骤

1. 建立清晰的原生字号层级和更合适的标准字重，保留用户的系统字号偏好，并避免把大号金额和图表水印不必要地放大。
2. 保留网页按模块设定的圆角层级，对齐共享卡片内边距、背景、边框、轻阴影及首页模块间距，并移除储蓄页重复的状态栏留白。
3. 优先调整首页标题、核心余额卡片与资金分配卡片，使其采用与网页新版一致的空间层级；保留原生数据和交互逻辑。
4. 构建调试版并在手机上检查首页实际排版、文字可读性和裁切情况；按截图结果修正。
5. 更新原生版版本记录和开发版本号，提交本地仓库，不推送 GitHub。

本轮首页样式确认后，按网页版页面顺序继续对照消费、储蓄、贷款、资产、设置，逐页迁移共享设计规则并检查各自的数据模块与交互。每轮以实际手机页面检查为准，不只凭代码推测。

## 消费分析 ECharts 与网页结构对齐

网页版消费分析使用 ECharts 6.1.0 绘制收支趋势、分类环图、商家排行、平台柱状图和消费流向桑基图；纯 KT 版曾以 Compose Canvas、自绘桑基图和普通列表替代，函数名带有 `ECharts` 但实际没有调用 ECharts，导致视觉、提示和数据交互不一致。本轮应让原生页真正使用 ECharts，并沿用原生账本数据与筛选状态。

执行步骤：

1. 将与网页一致版本的 ECharts JS 作为本地 Android asset 打包，图表使用本地资源离线渲染，不请求 CDN。
2. 新建可复用 Compose 图表容器，以 Android WebView 承载 ECharts；处理 Compose 重组时更新 option、尺寸变化时 resize、图表点击回传以及纵向手势交给外层 LazyColumn，避免图表挡住页面滚动。
3. 依照网页消费分析顺序替换趋势折线图、分类环图、商家排行横条图、按日/按月的平台堆叠柱图和账户到分类的桑基图。节律热力图在网页版由 HTML/CSS 网格实现，原生继续用 Compose 网格对齐其布局，不误称为 ECharts 图表。
4. 将首页消费构成、首页现金流趋势、贷款月供趋势/负债构成及资产配置构成中仍以 Canvas 绘制的分析图也替换为同一 ECharts 运行时；进度环和比例条属于指标装饰，继续由原生 Canvas 绘制。
5. 保留网页现有颜色、图例、金额提示、空数据状态和点击筛选语义；核对消费图表均使用当前筛选数据，并让桑基图节点/连线的点击回传到账户或分类筛选。
6. 递增原生调试版本和 Android `versionCode`，构建独立归档 APK 并安装到当前 Android 调试设备，检查首页、消费、贷款、资产图表显示、点击与纵向滚动；结束调试进程后更新本记录并本地提交，不推送 GitHub。

这是对已有消费分析展示的体验优化 / PATCH，不增加新的账本任务能力。当前基线为 `0.21.0-dev.12` / `versionCode 10044`。
