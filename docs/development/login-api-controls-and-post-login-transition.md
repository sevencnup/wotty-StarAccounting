# 登录页 API 检测与登录后过渡修复

## 用户期望

- 登录页始终显示云端 API 地址、连接状态和“检测 API 地址”按钮，检测成功后仍可查看及重新检测。
- 点击“登录并进入”且登录成功后，直接进入账本，不短暂出现“已登录／继续使用云端”或第二层 API 检测卡片。
- 自动恢复已有会话时，检测过程保持隐藏；连接失败时仍显示可操作的错误与检测入口。

## 原因

上一轮把 API 检测控件放入 `!apiVerified` 条件分支，误删了登录页验证成功后的检测入口。登录成功时，入口先更新 `cloudUser`，再等待模式切换和路由跳转，期间可能重新渲染入口卡片。

## 实施步骤

1. 恢复登录页 API 检测控件与登录表单同时显示的布局；无登录态时，自动检测过程也显示在登录页。
2. 为成功登录和会话恢复后的跳转增加不可见阶段，在更新账户展示状态前切入该阶段。
3. 跳转失败时恢复登录界面及错误提示。
4. 静态核对登录、手动检测、自动恢复和失败分支，更新版本记录并本地提交。

## 分类

修复 / PATCH：恢复已有入口和登录后的预期过渡，不改变用户可完成的任务。

## 完成记录

- 登录页重新常显 API 地址、检测状态和手动检测按钮。
- 无登录态时直接显示自动检测状态；已有会话自动恢复时保持入口隐藏。
- 登录或继续使用云端成功后，在路由切换前隐藏入口；失败则恢复登录页面与错误提示。
- 已核对所有入口状态分支、差异格式及当前开发服务的热更新编译状态。
