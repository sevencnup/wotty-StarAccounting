# 订阅选择器、录入页操作区与结余修复

## 需求与分类

修复订阅/扣费管理中的消费分类和支付平台选择弹层被父弹层遮挡的问题；让记账、储蓄计划和资产录入的保存操作在长表单滚动时始终可见；核对自动扣费流水与结余的同一笔记账关系。三项都是已有功能未按预期工作或操作不便，归类为修复/体验优化（PATCH）。

## 实施步骤

1. 让 ChoicePicker 的弹层高于设置页弹层，并保留原有返回、遮罩和关闭行为。
2. 调整 JournalPanel 内的保存操作区，使记账、储蓄计划、资产及同容器内的其他录入操作可在底部固定显示，内容仍可滚动到最后一项。
3. 沿自动订阅流水、消费统计、首页结余与预算余额的数据流定位差异；修复对应计算或刷新链路，避免一笔扣费重复计算。
4. 审阅改动并本地提交；安装包构建留待单独的发布任务。

## 验收范围

- 两个选择弹层能在订阅/扣费管理上方完整显示并操作。
- 长表单滚动时保存按钮始终可见，不遮挡最后一项输入。
- 已生成的订阅支出在对应结余口径中只扣减一次。

## 追补：录入页底部露出表单

用户截图显示固定操作区下方仍有一段表单内容露出。原因是录入面板底部仍有内边距（页面模式为 `20px + safe-area-inset-bottom`，普通弹层模式为 `24px + safe-area-inset-bottom`），而固定操作区的实色背景没有覆盖这段空间。

1. 让固定操作区的背景延伸到面板底部和系统手势区，保持按钮原有位置。
2. 检查同一操作区在记账、储蓄、资产等录入模式中的适用范围并本地提交。该追补仍是布局修复（PATCH），属于小调整，无需另写版本记录。

## 追补：固定按钮位置偏高

用户再次截图指出固定按钮下方留白过大。保留操作区向面板底部延伸的实色背景，缩小按钮下方的内部留白，让按钮靠近面板底部，同时继续给系统手势区域留空间。此项仍属布局修复（PATCH）。

## 追补：重做操作区与滚动区域的布局

前面的 sticky 与负边距方案没有解决问题：操作区仍在表单滚动容器内，受到父容器内边距、裁切和储蓄页限宽影响，底部与右侧继续露出输入框和表格。此项按原需求继续修复（PATCH）。

1. 先用手机尺寸的浏览器页面记录记账、储蓄页当前布局，使用隔离的示例数据。
2. 面板改为独立标题、可滚动表单和底部操作区；通过 React Portal 将各表单自己的保存操作放入面板底部，保留原来的保存逻辑。
3. 移除 sticky、负边距和补底留白；底部操作区横向铺满面板，表单只在其上方滚动。同步储蓄输入框自动滚动使用的容器。
4. 检查记账、储蓄、资产、薪资补录在不同滚动位置、窄屏、底部安全区和键盘可见区域缩小时的布局；确认保存按钮点击有效且只有一组操作。
5. 运行类型检查，保存对比截图，清理临时检查脚本与浏览器进程，再本地提交。

### 本次核对结果

- 手机尺寸浏览器复现旧布局：记账操作区距面板底边 20px，储蓄操作区还距右侧内边缘 28px，底部点位能命中表格输入框。
- 新布局在 390×844 下，操作区底边与面板同为 844px，两侧与面板内边缘对齐；按钮下方为 8px 留白，系统安全区另行保留。
- 记账、储蓄、资产新增/编辑、贷款和薪资补录完成 69 项布局检查，覆盖三种手机尺寸、不同滚动位置、储蓄表格横向滚动、24px 模拟安全区及键盘可见高度模拟。窄屏旧内边距规则同步修正。
- 隔离示例数据下，清空重填和记账、储蓄、资产保存均正常触发，没有浏览器异常；请求由临时浏览器环境拦截，未写入实际账本。
- TypeScript 类型检查通过。此为原布局修复的追补，不生成新的安装包或独立发布记录。
