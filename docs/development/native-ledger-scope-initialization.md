# 原生版账本数据源切换初始化

## 问题

纯 Kotlin 版首次组合时，流水快照始终从 `LOCAL/local` 读取，而其它实体会按当前登录状态读取本地或云端缓存。登录云端或退出云端后，数据刷新由 `LaunchedEffect` 延后执行；状态变量可能在刷新前短暂沿用上一个账本的数据。

## 目标

所有记账数据状态都按当前的数据范围和账本 ID 初始化。应用启动时直接展示当前模式对应的 SQLite 缓存；本地/云端模式或云端账号改变时，页面状态先切换到目标账本缓存，再异步向服务器刷新。首页、消费、储蓄、贷款、资产和设置不能短暂显示上一个数据范围的流水或实体。

## 实施步骤

1. 在 `StarkNativeApp` 中统一从 API 登录偏好推导当前 `scope` 和 `accountId`。
2. 为流水、余额、账本账户、资产、预算、贷款、储蓄目标/计划、订阅、归类规则和导入错误状态使用 `scope + accountId` 作为 `remember` 键；初始数据从同一账本范围的 SQLite 读取。
3. 保留生命周期恢复和云端刷新逻辑；网络刷新只更新当前账本状态，不改变本地与云端数据隔离规则。
4. 增加本阶段版本记录：`0.21.0-dev.2`，`versionCode 10034`。此项修复跨账本状态沿用问题，属于 PATCH。
5. 构建调试包并验收：本地冷启动；云端账号启动；登录、退出及切换云端账号；对照各范围账单、资产、预算、贷款、储蓄、订阅和归类规则缓存；确认切换前后的记录不会串显，云端刷新失败仍仅展示当前云端账号缓存。

## 验收边界

- 启动时流水和余额来自当前模式与账号对应的 SQLite 记录。
- 切换登录状态或云端账号后，各实体状态与目标账本缓存同步切换。
- 生命周期恢复只刷新当前范围，不把另一范围的本地偏好或账单写入云端。
- 验收过程不新增、修改或删除真实账单。

## 分类与版本

这是对已有本地/云端账本隔离行为的修复，用户可见流程没有新增，版本为 `0.21.0-dev.2` / `versionCode 10034`。
