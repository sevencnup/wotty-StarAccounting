# 纯 Kotlin 设置与账单维护开发计划

## 目标

对照 Web 设置页 `app/src/app/app/(tabs)/accounts/page.tsx`，逐步补齐原生设置入口、周期扣费、账单归类、账单导入/导出、界面偏好、账户操作和帮助信息。设置里的账单写入必须使用当前本地或云端账本，导入先预览再确认，重复账单不能重复记入，失败行保留重试信息。

## Web 能力与数据契约

- **订阅/扣费管理**：`Subscription` 包含 `name/amount/billingDay/category/platform/paymentMethod/startDate/isActive`。每月按设定日生成消费流水；短月份把 29–31 日压到月末。流水 ID 与订阅和月份确定性绑定，启动或恢复时补记到期月份且可安全重复调用。停用或删除订阅不会删除历史流水。
- **账单归类**：`CategoryRule` 按账单关键词匹配已有流水并设定 `remarkCategory`；可查看/修改规则、启用/停用、删除。导入时先应用启用规则，再匹配贷款还款并写入对应贷款。
- **导入/导出**：微信、支付宝 CSV/XLS/XLSX 和本应用 CSV；导入须预览、确认、检测重复、保存失败行及错误原因并允许重试。导出当前账本完整流水为 UTF-8 BOM CSV，包含日期、类型、分类、备注归类、商户、平台、金额、支付方式、状态、订单号、说明和贷款 ID。
- **界面偏好**：语言为跟随系统/简体中文/英文，字号为较小/标准/较大；选择持久保存。
- **账户/模式**：当前云端账户可修改密码、管理是否开放注册并退出；本地模式可回到模式入口。原生端当前以云端 token 是否存在选择 `LOCAL` / `CLOUD` 数据域，切换不能合并或覆盖两边数据。
- **帮助/关于**：导入格式、数据加载和云端说明、版本信息与项目反馈入口。

## 实施阶段

### 阶段 A：设置壳层和周期扣费

1. 将设置主页改为与 Web 分组相近的原生入口，并增加可复用的底部弹层导航；保留云端连接、刷新和当前版本信息。
2. 实现订阅实体解析、SQLite 本地/云端缓存隔离、API 读写与删除。
3. 实现订阅新增、编辑、启用/停用、删除；校验名称、金额、记账日、分类、平台和开始日期。
4. 移植月末日期规则与确定性流水 ID；启动、应用恢复和设置页打开均可补记到期项，写入前按 ID 与订单号防重。
5. 订阅生成的流水写入当前账本，云端以服务端成功为准；保存后消费、首页、资产和贷款共享状态刷新。

### 阶段 B：规则和账单维护

1. 实现分类规则列表、启用/停用、编辑/删除及匹配预览；对历史流水批量应用规则，保留原流水字段。
2. 实现 Android 文件选择器导入 CSV，适配微信、支付宝和本应用格式；展示确认预览和重复数，再执行导入。
3. 保存失败行、原始行和错误信息；提供失败行重试，确保重复确认不会重复生成流水。
4. 导出当前账本完整流水为 UTF-8 BOM CSV，通过系统保存文件面板生成新文件。
5. 支持贷款还款规则匹配并使用既有服务端原子接口；导入失败时明确显示部分成功结果。
6. 后续再补 XLS/XLSX 工作簿读取，若 Android 无合适现有库则以独立解析实现，不伪称支持。

#### B1：账单归类规则验收步骤

1. 增加与 Web `CategoryRule` 字段一致的原生模型，并为 `LOCAL` 和 `CLOUD` 账本分别读写规则。
2. 在设置页提供关键词输入、消费分类选择、命中流水预览及规则列表；匹配忽略大小写和空白，覆盖商户、说明、平台、支付方式、分类和订单号，不匹配收入。
3. 保存/编辑规则后，将其应用到所有命中流水，只更新 `remarkCategory` 与 `updatedAt`，其余流水字段保持原值；云端写入失败时显示错误，不伪报成功。
4. 支持启停与删除。启停只影响后续规则使用；删除规则保留已经写入流水的分类。
5. 真机用临时规则验收预览、保存、重载、启停、编辑和删除；验收完成后清理临时规则及临时归类，核对消费金额恢复。
6. 构建并安装新的调试副本、更新版本记录与验收文档，通过 `git diff --check` 后只提交本地 Git。

#### B2：原生账单 CSV 导出验收步骤

1. 按 Web `transaction-csv.ts` 保持 13 个字段及字段顺序，类型映射使用“收入/支出/转账/还款”；转义逗号、双引号和换行。
2. 文件使用 UTF-8 BOM 与 CRLF 行尾，金额输出十进制文本；导出当前账本的全部流水，不改写账本数据。
3. 在设置页提供导出说明和系统“创建文档”保存面板；用户取消、权限失败、写入失败和成功均显示明确状态。
4. 真机导出到系统 Downloads，核对 BOM、表头、13 列、流水行数及金额精度；删除验收文件并确认账本笔数与总额不变。
5. 构建并安装新调试副本，记录版本与验收结果；通过 `git diff --check` 后只提交源码、文档和版本记录。

#### B3：原生账单 CSV 导入实施与验收步骤

1. 增加 Android 系统文件选择器，只接受 CSV；读取 UTF-8/UTF-8 BOM，识别微信、支付宝和本应用导出格式，正确处理引号、逗号、换行和 CRLF。
2. 按 Web `bill-csv.ts` 映射日期、金额、流水类型、分类、备注归类、商户、平台、说明、支付方式、状态和订单号；本应用导出额外保留流水 ID。格式无法识别或单行字段无效时，保留原始行、行号及错误原因，不能静默丢弃。
3. 确认导入前展示来源、可导入数、重复数和错误行；重复项按已有流水 ID、订单号及本次文件内重复项识别。没有稳定 ID/订单号的账单不按金额与日期猜重，避免误删真实的分笔消费。
4. 预览并应用启用中的账单归类规则，再按 Web `loan-repayment.ts` 规则匹配唯一且未结清的贷款；不能唯一匹配时保留原交易类型，不自动冲还贷款。
5. 用户确认后写入当前 LOCAL/CLOUD 账本：本地导入在同一数据库事务内保存；云端使用 `/api/transactions/import?accountId=...`，按接口回传的导入、跳过、失败和贷款还款结果显示部分成功信息。失败不得提示为全部成功。
6. 将失败行及原因保存到当前账本的数据域，允许查看并重试；重试再次执行 ID/订单号防重，确保已成功行不会被重复记账。
7. 真机分别验收本应用导出 CSV、微信/支付宝样例、含逗号和引号的字段、无效行、重复文件及部分失败；验证本地与云端写入范围隔离。验收产生的临时账单必须清理并复核账本金额。
8. 完成后递增原生版本与 `versionCode`，更新本文件验收记录及 `CHANGELOG.md`；保留新的调试 APK，执行 `git diff --check` 并只提交源码、文档和版本文件到本地 Git，不推送 GitHub。

### 阶段 C：偏好、账户与收尾

2. 接入云端密码更新、注册状态管理与注销确认；不在本地保存管理员恢复密钥。
3. 完善本地/云端入口、帮助、关于、版本和反馈链接。
4. 每阶段按用户可见能力递增版本与 `versionCode`，更新原生变更记录和本文件验收记录。
5. 真机验证关键读写与跨页刷新，保留独立调试 APK；检查 `git diff --check` 后只提交源码、文档和版本文件到本地 Git，不推送 GitHub。

#### C1：界面语言与字号设置实施及验收步骤

1. 对照 Web `ui-settings.ts` 与账户设置页，使用 `SYSTEM/ZH_CN/EN_US` 和 `SMALL/STANDARD/LARGE` 选项；默认简体中文与标准字号。
2. 将选择保存在设备偏好中，切页和重启后保持；`SYSTEM` 按 Android 当前系统语言解析，字号变更即时生效且保留系统无障碍字号比例。
3. 通过 Compose 全局本地化入口覆盖所有原生页面、底部导航、弹层、提示和动态状态；复用 Web 已有翻译词条及动态格式，逐项补齐原生独有文案后才显示英文选项。
4. 设置页提供语言和字号选项弹层，显示当前值、语言说明和字号样例；选择后即时更新设置页和应用其余页面。
5. 真机分别切换中文/英文及三档字号，跨页面检查导航、表单、图表、弹层和动态金额；重启应用确认设置持久化，并确认设备无障碍字号变化仍能叠加。
6. 递增原生版本和 `versionCode`，记录验收结果与 `CHANGELOG.md`；构建安装独立调试包，执行 `git diff --check`，本地提交源码、文档和版本记录，不推送 GitHub。

#### C2：云端账户设置实施及验收步骤

1. 对照 Web `app/src/app/app/(tabs)/accounts/page.tsx` 与 `cloud-auth.ts`，确认密码修改使用 `POST /api/auth/password`，注册状态读取使用 `GET /api/auth/registration`，注册开关使用带登录令牌与 `adminKey` 的 `POST /api/auth/registration`。
2. 仅在云端登录状态下显示账户设置与退出入口；密码输入至少 8 位且两次一致，提交时禁用按钮并展示服务端错误/成功状态，成功后立即清空密码字段。
3. 注册设置打开时读取服务端状态；每次更改都要求输入部署管理员恢复密钥。密钥只保存在界面临时状态，不写入数据库、偏好或日志，提交后清除；服务端返回值为唯一成功状态来源。
4. 退出云端前提供原生确认框；确认后清除会话 token 与云端账户选择，回到本地数据域，不删除本地账本，不把云端缓存并入本地账本。
5. 真机检查本地模式不显示云端账户操作；云端界面检查状态加载、密码校验、管理员密钥必填、请求忙碌/失败/成功状态和退出确认。不得在真实用户账户上修改密码或改变服务端注册开关；只用可控的开发服务验证会写入的接口。
6. 递增原生版本与 `versionCode`，更新 `CHANGELOG.md` 和验收记录；构建安装独立调试包、检查 `git diff --check` 并提交源码、文档和版本文件到本地 Git，不推送 GitHub。

#### C3：数据模式、帮助、关于和反馈入口实施及验收步骤

1. 对照 Web 设置页的 HELP/ABOUT 内容及当前原生数据流，清晰标注本地/云端当前来源、连接/切换账户入口与退出回本地操作；确保所有退出入口都要求确认。
2. 将帮助改为可滚动底部面板，说明本地与云端账本隔离、数据加载排查、原生 CSV 导入支持范围和 Web/原生差异；不宣传尚未实现的 XLS/XLSX 导入能力。
3. 将关于页改为可滚动底部面板，显示应用名称、原生版本、项目简介、Kotlin/Compose 技术信息，并提供博客、项目网站、GitHub 开源仓库链接。
4. 在帮助面板提供 GitHub Issues 与国内项目反馈链接；使用系统浏览器打开外部地址，链接文本随应用语言翻译。
5. 真机检查本地模式说明、云端模式入口与退出确认，检查帮助/关于/反馈内容滚动和链接启动；无需登录真实云端账户，也不提交外部反馈。
6. 递增原生版本和 `versionCode`，更新变更记录与本文件验收结果；构建安装独立调试包，执行 `git diff --check`，仅本地提交源码、文档和版本文件。
