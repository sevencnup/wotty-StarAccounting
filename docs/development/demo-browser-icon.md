# 演示页面浏览器图标

## 问题与分类

- 宣传站首页通过 `/logo.webp` 声明浏览器图标；嵌入的手机演示和独立 Web 演示由 Next.js 静态导出，其根布局没有图标元数据，导出的 HTML 因此没有 `rel=icon` 标签。
- App 已有 `app/public/logo.webp` 品牌图标。两套演示将文件复制到各自导出根目录，但当前页面头部没有引用它。

本次属于修复（PATCH）：为已有演示页面补齐浏览器标签及书签图标，不增加新的用户能力。应用版本从 `0.7.4-dev.1` 递增至 `0.7.5-dev.1`，Android `versionCode` 从 `158` 递增至 `159`；宣传站从 `0.5.2` 递增至 `0.5.3`。不构建 APK。

## 执行步骤

1. 在 Next.js 根布局元数据中引用现有 Logo，并在构建时根据演示 `basePath` 生成可访问路径。
2. 更新应用版本、Android 版本码和版本记录。
3. 依次重建手机和 Web 静态演示，校验导出的 HTML 均声明指向对应演示根目录的 favicon。
4. 通过本地开发服务打开页面并检查图标资源的响应和内容类型，再运行宣传站生产构建。
5. 恢复 Next.js 自动改写的类型声明，保留已有构建产物和私人笔记，分别本地提交应用及宣传站。

## 验收

- 手机演示和 Web 演示 HTML 均有 `rel=icon`，路径分别落在 `/phone-demo/logo.webp` 和 `/web-demo/logo.webp`。
- 页面声明的每个图标地址在开发服务返回图像文件，而非 SPA 首页。
- 宣传站根首页已有的图标继续正常加载。
- 应用类型检查和宣传站生产构建通过；不创建安装包。
