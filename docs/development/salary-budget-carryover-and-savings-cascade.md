# 发薪预算、上期结转与储蓄计划联动

## 目标与口径

- 顶部结余卡保持当前账本余额为主数，在月度结余明细中增加“发薪前结转”。优先取所选月份发薪日当天及之后的首笔工资作为起点；若没有，则取该月最早一笔。结转是这笔工资入账前的已核实余额；若余额基准缺失或晚于这笔工资，不倒推也不显示为零。
- 本月资金分配卡把储蓄计划的固定支出、临时支出逐项列出，并在明细之后展示“发薪后预计可支配”。计算口径为本月已入账工资 + 已核实发薪前结转 − 计划固定支出 − 计划临时支出 − 预计存款。结转不可核实时，仅计算工资部分并明确提示。
- 预计可支配是发薪时的计划数。当前实际余额和真实消费、还款、存款继续独立展示；不以未关联的流水自动抵销计划项目，也不重复扣减实际账本。
- 首页不再同时展示储蓄表自身的“预计剩余”，避免与按真实工资和结转计算的发薪预算出现两个不同的预计数字；储蓄表仍保留其逐行预计剩余。
- 没有工资入账时展示计划明细，但不生成发薪后预计可支配；年度视图保留计划汇总，不生成跨月的发薪预算。
- 储蓄表编辑工资、预计存款或固定支出时，默认从当前行向下同步，之前月份保持原值；可选“仅本月”。临时支出和上月结余始终只修改当前行。

## 实施步骤

1. 从真实工资流水和余额基准计算发薪前结转及工资预算起点，明确无基准和历史月份的空值行为。
2. 调整首页资金分配卡层级：先列计划项目，再给发薪后预计可支配，并保留实际金额区及两种口径说明。
3. 顶部月度结余明细展示发薪前结转；补齐中文与英文及窄屏样式。
4. 改储蓄计划的行编辑联动和“仅本月”选项，保证不同频率的月份顺序互不串改。
5. 静态核对发薪截止、余额基准、重复扣减、行联动和版本文件；本轮不增加或运行测试。记录版本描述并只提交本地 Git。

## 注意事项

- 工资以收入流水的“工资、工资收入、薪资、薪水”分类识别；用流水入账时间作结转截止，不能用操作时的当前时间。
- 一个期间有多笔工资时，预算工资只合计选定起点及之后的工资。更早入账的工资已包含在结转中，不能再次相加。
- 后续流水已经记账时，计划预算仍表示发薪时的预计值，不宣称是实时剩余额度。
