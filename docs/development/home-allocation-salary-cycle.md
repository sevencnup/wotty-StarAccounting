# 首页资金分配跟随发薪周期

## 现状与目标

首页资金分配的实际收入、消费、还款及储蓄按所选自然月统计，修改发薪日不会改变这些数值；顶部结余的发薪周期则使用发薪日至下次发薪日前的区间。让资金分配卡按同一个发薪周期展示实际金额，并让下半部分储蓄计划对应周期起始月份。年度视图继续按自然年汇总。

## 数据口径

- 月度视图复用现有 `salaryCycleRange`：历史月份从该月发薪日开始；当前月份在发薪日前显示上一发薪周期。卡片写明起止日期，标题用“本期资金分配”。
- 实际收入、消费、还款、储蓄都取这个周期内已入账记录；资产存量仍是独立余额，不参与周期扣减。
- 计划区使用周期起始月份的已保存计划；已入账工资与发薪前结转也使用该月份的工资起点。计划金额仅供预计，不混入上方实际净额。
- 年度视图保留原有全年实际与全年计划汇总，不生成跨月的发薪预算。
- 首屏数据需覆盖周期可能延伸至的下一个自然月，避免先显示缺少跨月记录的金额。

## 实施步骤

1. 在首页汇总中以发薪周期计算月度资金分配，年度保持原口径；确定计划对应月份及该月工资规划来源。
2. 更新卡片标题、范围说明和计划月份标记，确保实际区与计划区口径清楚。
3. 扩大月度首屏流水加载范围，覆盖所选发薪周期的末月。
4. 静态检查周期边界、发薪日前、历史月份、年度视图、数据加载和版本文件；不增加或运行测试。
5. 按统计口径扩展分类更新中版本和更新描述，仅提交本地仓库。

## 验收重点

- 改发薪日后，月度卡片实际收支随周期起止变化；跨月账单只计入所属周期一次。
- 本月发薪日前，卡片明确显示上一个周期，并读取其起始月份计划与工资。
- 展开计划后，工资来源、支出计划和预计可支配采用同一个计划月份。
- 年度卡片数字与原全年统计一致。
