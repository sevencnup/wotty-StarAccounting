# Docker Compose 首次零配置部署

## 目标

新用户拉取仓库后直接执行 `docker compose up -d --build`，无需预先知道 `.env` 或手动设置数据库密码，也能启动 MySQL、Go API 和 Web。首次启动生成的密码与登录密钥必须保存在 Docker 数据卷中，后续重启和更新继续使用，且不得打印到日志。

## 现状

Compose 对 `MYSQL_ROOT_PASSWORD`、`DB_PASSWORD` 和 `JWT_SECRET` 使用必填插值。没有 `.env` 时，Compose 在创建容器前就会失败；同时默认 `API_HOST` 是某台机器的固定地址。MySQL 容器能在空数据卷中建库，但 API 需要与它共享同一应用账号密码。

## 实施步骤

1. 增加一次性密钥初始化服务。优先使用首次部署时显式提供的环境变量，否则为 MySQL root、应用账号、JWT 和管理员恢复密钥生成随机值，分别写入持久化数据卷；已有密钥保持不变。
2. MySQL 使用官方镜像支持的 `MYSQL_ROOT_PASSWORD_FILE`、`MYSQL_PASSWORD_FILE` 读取密钥；Go API 镜像的启动脚本从对应文件加载应用密码、JWT 和管理员恢复密钥。
3. Compose 等待密钥初始化完成后再启动 MySQL，等待 MySQL 健康后再启动 API；移除首次部署必填插值，并修正 API 监听地址默认值。
4. 更新 `.env.example`、README 和数据库部署文档：零配置启动、已有 `.env` 的兼容方式、查看自动生成密码、数据卷备份与外部数据库的边界。
5. 检查无 `.env` 的 Compose 配置可解析，审查密钥初始化和已有数据卷的处理。真实空库部署留待用户明确要求验证时，在隔离项目名与端口下执行。
6. 记录用户可见变化，并将本次修改提交到本地 Git；不推送 GitHub。

本次让新用户无需预先配置密钥即可完成首次部署，属于新增功能（MINOR）。根工作区版本从 `0.0.2` 递增到 `0.1.0-dev.1`；Android 客户端源码和安装包未变。

## 验收标准

- 无 `.env` 时 Compose 配置可解析，空数据卷首次启动设计上可由 MySQL 建库、Go API 建表，API 健康检查目标为 `db:true`。
- 密钥在容器重建后保持一致，日志不包含密钥，现有 `.env` 配置仍能在首次生成密钥文件时使用。
- MySQL 自动创建数据库和应用账号，Go API 自动创建业务表；外部 MySQL 仍需要先建库和账号。
- 当前仓库的本地 `web/` 不进入发布内容。
