# 纯 Kotlin 账本余额基准

## 目标

对照 Web 账本模型，把“余额基准金额 + 基准日期”接入纯 Kotlin 版。用户可在设置中录入某日 00:00 已确认的实际余额，首页和资产页使用该基准累计后续真实流水。保存只更新账本字段，不创建余额校正流水。

## Web 口径与原生差异

- Web `Account` 已有 `openingBalance` 和 `openingBalanceDate`；本地 IndexedDB 与云端 `/api/accounts` 已支持读取和保存。
- Web 从基准日开始累计收入、消费、还款和已完成储蓄的实际存入；转账不改变账本总余额。早于基准日期的账单不参与余额推算。
- Web 设置面板的实现参考 `AccountReconciliationSheet.tsx`，但目前该组件没有挂到页面入口；首页发薪周期详情会展示已保存基准与日期。
- 纯 KT 目前没有账本账户模型；本地余额以单独的 `actualBalance` 存储，云端同步则把资产余额合计作为该值。没有设置基准时须保留当前兼容显示。
- API 已提供当前用户账本的 `GET /api/accounts/{id}` 和 `POST /api/accounts`，字段包含 `id/name/ownerId/openingBalance/openingBalanceDate/createdAt/updatedAt`。

## 实施步骤

1. 新增原生账本账户模型与余额计算函数；按本地/云端模式及账本 ID 隔离保存基准字段，本地写入原生 SQLite `accounts` 实体，云端使用现有账户 API。
2. 在设置增加余额基准入口和 Compose 面板，显示基准日、输入金额、基准后收入/支出/还款/实际储蓄、纳入账单数及当前余额预览；拒绝空日期和非数字，不生成流水。
3. 云端登录后读取指定账本的账户字段；保存成功后更新原生状态和缓存，失败时保留旧值并显示错误。未连接云端时只写本地账本。
4. 已设置基准时，首页当前结余和资产页的账本余额回退值按“基准金额 + 基准日及之后的净流水”计算。流水新增、编辑、删除、导入和自动记账后重算；基准日前流水不影响余额，转账不影响总余额；已完成储蓄按实际存入日期和金额扣减。未设置基准时沿用现有值。
5. 增加简体中文和英文界面文案；更新完整开发清单与版本记录。这是用户此前不能完成的账本余额基准设置，按新增功能 / MINOR 递增到 `0.17.0-dev.1`，Android `versionCode` 递增到 `10027`。随后将本地账户基准从偏好文件迁入 SQLite `accounts` 实体，记为 `0.17.0-dev.2` / `versionCode 10028`。
6. 构建独立调试 APK 并安装真机。使用调试副本的本地账本做基准保存、日期边界、收支/还款、转账、编辑/删除重算及重启持久化核对；验收后清理临时基准或还原到测试前状态，不改动真实账单。云端写入只有在已登录且能确认使用隔离测试账本时才验收。
7. 执行 `git diff --check`，更新验收结果，只把本轮源码、版本与开发文档提交到本地 Git，不推送 GitHub、不纳入 APK 和构建目录。
