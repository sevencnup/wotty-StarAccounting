# 纯 Kotlin 旧式 XLS 账单导入

## 目标

补齐纯 Kotlin 设置页对旧式 `.xls` 工作簿的读取能力，并继续复用现有预览、来源识别、重复检测、失败行记录和确认导入流程。

## 已核对的 Web 规则与原生差异

- Web 入口为 `app/src/lib/stark/import/bill-csv.ts`，用 `xlsx` 库读取 `.xls` / `.xlsx` 的第一个工作表，再走共同的账单字段映射。
- 原生端已自行实现 XLSX 首工作表读取、CSV 字段映射和导入去重；当前在文件选择回调中明确拒绝 `.xls`，帮助页也提示另存格式。
- 新解析器只负责把第一张表转换为原生行记录，后续流程复用 `parseNativeBillRecords`，避免两套映射和导入规则。

## 实施步骤

1. 采用轻量的 HSSF 读取库解析旧式 XLS；限制文件字节数、行数和列数，避免超大工作簿拖垮手机。
2. 把第一个工作表的单元格转为现有原生表格记录，保留表头位置、日期值及原始行文本。
3. 在设置导入入口允许 `xls` 并复用已有预览、重复、失败行和确认导入流程；更新帮助、导入提示与英文文案。
4. 递增原生 MINOR 版本和 `versionCode`，更新 `CHANGELOG.md` 与完整开发清单。
5. 构建 `.dev` APK，在手机用一个无业务关联的 XLS 样例验证选择、识别、预览和取消/清理行为；不要留下测试流水。

## 验收范围

- `.xls`、`.xlsx`、CSV 的格式提示准确；旧式 XLS 不再被拒绝。
- 第一张工作表的表头偏移、日期、金额、类型和字段映射进入统一导入预览。
- 重复账单仍在确认前识别；取消预览不会写入账本。
- 超出文件/工作表限制时给出明确提示，不写入数据。
- 真机测试数据导入后清理，原有账单总额恢复。

## 版本分类

让原生版能导入原先无法读取的账单格式，属于新增功能 / MINOR。目标版本为 `0.21.0-dev.1`，Android `versionCode` 为 `10033`。
