# 修复周期支出删除时的排序规则冲突

## 问题

云端删除周期支出返回 HTTP 500，Kotlin API 报 `Illegal mix of collations (utf8mb4_0900_ai_ci, utf8mb4_unicode_ci) for operation '='`。删除前的账户归属校验用 `subscription.accountId IN (SELECT account.id ...)` 直接比较两列，旧账户表和新订阅表使用了不同的排序规则。

## 实施步骤

1. 将 Kotlin API 的订阅归属校验拆为按订阅 ID 读取账本 ID、再按该 ID 和当前用户查询账户，避免两列直接比较。通用同步删除和 REST 删除都复用此校验。
2. 保持原有权限约束、删除行为和历史流水保留规则；不迁移或改写数据库数据。
3. 静态检查受影响的权限分支及版本记录；本次不增加或运行测试。
4. 更新本地开发 API 进程以载入修复，只提交本地 Git，不推送 GitHub。

## 验收重点

- 当前用户只能删除自己账本下的周期支出，其他用户的记录仍被拒绝。
- 删除请求不再触发两列排序规则冲突，已生成的历史流水保持原样。
- 保存、读取和启停周期支出保持现有行为。
