# 在线演示账本按月自动推进

## 目标

宣传站的手机和 Web 演示使用一个按真实日历推进的本地演示账本。每个月的收入在 1 万至 2 万元之间，由固定种子生成；同一个月份在不同设备或刷新后得到相同的示例金额。支出、储蓄、还款与资产必须来自同一批事件，不能为页面各自随机填数。

## 边界

- 仅在 `NEXT_PUBLIC_SHOWCASE_DEMO=1` 的隔离演示库运行；普通 App 的本地和云端账本不受影响。
- 保留 2026 年 8–10 月已有演示及访客在演示页自己新增、修改的数据。自动生成只补缺项，不重写访客记录。
- 以用户设备的当地日期为准：历史月份补齐，当月只产生已到日期的事件；未来月份不预先记账。
- 生成记录使用年月、事件类型及序号组成的固定 ID。再次进入、刷新、跨页面打开或跨月回访均不重复入账。
- 当月计划先显示待存，到计划日再完成；贷款余额、已还期数及资产余额只随实际生成的事件变化。

## 开发步骤

1. 抽出可测试的月度样本生成器：固定种子的收入、分类支出、两笔贷款还款和储蓄计划，所有日期和金额可复现。
2. 在演示账本启动时进行从 2026 年 10 月既有数据之后到当前日期的补账。使用原子化写入处理交易、计划、目标、贷款和资产，按已有 ID 跳过已生成事件，并保护访客编辑。
3. 默认把自动演示定位到当前月。旧版固定的 `2026-10` 视为默认值并迁移；其他已选月份及此后访客主动切换的月份保持不变。
4. 增加跨月、同月重进、收入范围、储蓄完成、贷款减少和资产现金流一致性的测试。
5. 构建 App，再重新生成宣传站手机与 Web 演示，验证两端一致；最后按新增功能分类更新版本记录并进行本地提交，不推送远程。
