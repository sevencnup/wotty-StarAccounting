# 纯 Kotlin 原生版完整开发计划

## 目标

把纯 KT 版从首页演示补成可日常使用的原生记账应用。所有应用页面和交互使用 Kotlin 与 Jetpack Compose，不通过 WebView 显示网页。继续使用独立包名 `com.wotty.stark.nativeapp`，与 Web 壳版、KT 混合版并存安装。

## 现状

- 纯 KT 工程曾在 `native-app/`，最近一版源码可从提交 `c5a3151` 恢复；当前工作分支没有这个模块。
- 已恢复的实现包含 Compose 首页、按月消费汇总/分类筛选/账单列表、储蓄进度概览、贷款及资产明细概览、云端连接设置和快速记账。
- 目前各业务页以读取和统计为主；新增、编辑、删除、储蓄计划记录、贷款还款和设置管理尚未补齐。
- 本地数据目前以 JSON 保存在 `SharedPreferences`，云端同步只覆盖了流水、资产余额及首页预算/贷款/储蓄摘要，不能支撑完整功能。
- 网页端已有六个主页面：首页、消费、储蓄、贷款、资产、设置，以及记账、储蓄记录、资产/贷款管理、扣费管理等操作流程。

## 实施顺序

1. **恢复工程与版本身份**：恢复纯 KT 工程和 Compose 首页；将 `:native-app` 纳入当前 Gradle 工程；核对包名、图标、构建脚本和 APK 归档命名。更新版本区分文档，避免与 KT 混合版混淆。
2. **建立数据基础**：把 UI 状态、领域模型、云端 API、本地持久化拆开；以 Room 保存本地账本及页面缓存，复用现有认证和账本 API；明确本地模式与云端模式的数据隔离、错误提示和刷新行为。先盘点 `/api/sync` 与各业务 API 字段，写操作以服务端返回成功为准。
3. **完成消费与记账**：消费页支持月份、收支类型、分类/账户筛选、汇总图表及流水列表；记账支持支出/收入、日期、分类、账户、备注、编辑和删除，并从消费页与首页入口打开。
4. **完成储蓄**：实现目标组、月度计划、计划金额编辑、实际存入记录、凭证、完成状态和目标进度；按现有网页逻辑匹配已记账消费，避免首页、储蓄页和资产汇总口径不一致。
5. **完成资产与贷款**：资产页显示净资产、资产/负债分类和账户明细，支持新增、编辑、删除及余额校正；贷款页显示总览、还款节奏和明细，支持新增、编辑、还款记录、账单关联及删除。
6. **完成设置**：实现本地/云端账本入口、云端登录与账户、API 地址、账单导入/导出、订阅/扣费管理、账单归类规则、语言/字体和关于信息。缺少 Android 可用接口的能力先明确标注并补齐 API，不伪造成功状态。
7. **统一收尾**：统一原生页面导航、弹层、加载/空数据/错误/重试状态和无障碍标签；更新纯 KT 版本记录与安装包版本号。每次形成可独立安装验证的版本，APK 使用递增 `versionCode` 和新文件名保存。

## 页面与操作验收范围

- 六个底部主页面都展示真实数据，并具备可用的空数据、加载失败和重试状态。
- 主要新增、编辑、删除和还款/储蓄记录操作实际写入当前选定的数据模式；页面返回后相关总额、进度和列表同步更新。
- 云端账本使用现有 API 与鉴权；离线或 API 失败时保留可读缓存并清楚显示同步状态。
- 本地账本数据保存在应用私有 Room 数据库中，不与云端账本混用；清除数据/卸载风险在设置或说明中交代。
- 纯 KT APK 保持 `com.wotty.stark.nativeapp`，页面实现不引入网页套壳，也不覆盖另外两个 APK。
