# 纯 Kotlin 贷款模块开发与验收

## 目标

对照 Web 贷款页 `app/src/app/app/(tabs)/loans/page.tsx`，在 Jetpack Compose 中实现贷款总览、还款分析、贷款增改删和还款登记。按当前数据模式写入：本地模式写入独立本地账本，云端模式以服务器写入成功为准并更新云端缓存；两种数据不串账。保存失败时保留表单并展示错误，成功后刷新贷款、流水和首页统计。

## Web 数据和交互契约

贷款字段来自 `app/src/lib/stark/models/types.ts`：

- `id/userId/accountId/platform`
- `totalAmount/remainingAmount`
- `periods/paidPeriods/monthlyPayment/dueDate`
- `status`（`ACTIVE`、`PAID_OFF`、`OVERDUE`）
- `matchKeywords/createdAt/updatedAt`

页面按活动贷款汇总待还本金、已还金额和比例、本月月供、月供收入占比，以及最近还款日；提供未来六个月月供趋势、贷款余额构成、还款时间表和全部贷款进度。每笔贷款支持新增、编辑、删除和记录还款。

Web 还款表单保存一笔 `REPAYMENT` 流水，设置 `loanId`，金额不能超过剩余本金，并同步递增已还期数（只有金额达到月供时递增）；余额归零时贷款状态改为 `PAID_OFF`。普通 `POST /api/transactions` 不会自动冲减贷款。服务端已有 `POST /api/transactions/loan-repayments`，能把未关联的还款流水关联到贷款并在同一数据库事务中冲减本金和更新期数。原生手工还款先用固定流水 ID 写入未关联流水，再调用此接口；重试时先查询该 ID，已经关联成功就直接视为完成，避免重复扣减。

## 原生实现范围

1. 扩充原生贷款实体，保留 Web 字段并解析历史响应的缺省值。
2. 在本地实体库增加按数据范围隔离的贷款读取、保存和删除；云端响应只写入 `CLOUD` 缓存。本地手工还款的流水和贷款更新放入同一 SQLite 事务。
3. 增加贷款保存和删除 API 客户端方法，按当前 token、用户和账本 ID 请求。
4. 贷款页补全总览卡片、六个月趋势、构成、到期列表和贷款组合。
5. 增加贷款新增/编辑表单，校验名称、总额、剩余本金、期数、月供和还款日；匹配关键词可选。
6. 增加还款表单，限制正金额且不超过剩余本金；保存关联 `REPAYMENT` 流水并更新贷款。
7. 删除前二次确认；错误时保留当前表单，避免静默丢失输入。
8. 成功写入后刷新贷款和账单状态，首页待还、本月还款及贷款进度同步。

## 实施步骤

1. 先完成本地/云端贷款存储、API/模型适配和领域计算，统一日期边界、状态和金额取整口径。
2. 重建贷款页布局，按 Web 顺序实现指标、趋势/构成、日程和组合卡。
3. 接入新增、编辑、删除和还款表单；所有写入显式处理服务端错误。
4. 更新版本记录和完整开发清单，升级到下一个 `0.6.0-dev.1`（`versionCode 10007`）。
5. 构建仅用于调试副本的 APK，保留历史包；安装到 `com.wotty.stark.nativeapp.dev` 真机验收。
6. 真机验收涵盖本地/云端隔离、空列表、指标与贷款卡片、贷款新增后重载、字段编辑、删除、部分还款、达到月供时的期数变化、结清状态、首页/流水联动及错误反馈。使用临时贷款和流水时，记录原始状态并在验收后清理。
7. `git diff --check` 后将本模块源码、版本和文档提交本地 Git，不推送 GitHub。

## 当前发现和限制

- `GET/POST/DELETE /api/loans` 已存在；云端保存使用 POST upsert。
- 云端手工还款使用既有原子归类接口；首次写入未关联流水后遇到网络错误时，固定流水 ID 和重试前查询用于恢复，不重复冲减贷款。
- 当前原生贷款页只展示活动贷款的待还总额、月供及基础明细；本地贷款仓库、还款字段、分析图表和写操作均未接入。
- 每次完成写入都必须刷新本页贷款及首页共享状态；设备仅安装调试副本，不覆盖 `com.wotty.stark.nativeapp` 正式包。
