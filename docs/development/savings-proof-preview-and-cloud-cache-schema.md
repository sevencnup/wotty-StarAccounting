# 云端数据库版本同步与储蓄凭证预览

## 目标

- 提高底部“记账/添加储蓄”等悬浮按钮，避免与底栏重叠。
- 允许在储蓄计划的已存记录及编辑面板查看凭证大图。
- 服务端数据库新增表、字段或索引时，启动迁移并向 App 暴露数据库结构指纹。
- App 每次启动首次访问云端时读取结构指纹；指纹变化后清空该用户的旧云端响应缓存并重新拉取。
- API 响应模型变化时用独立的契约版本触发相同缓存刷新。

## 实施步骤

1. 调整悬浮按钮相对底栏的间距，兼顾安全区域与 KT 混合版底栏。
2. 增加可关闭的图片大图预览，在储蓄计划列表与记录编辑面板接入。
3. Go 服务根据声明的表、字段、索引定义生成稳定的结构指纹，并暴露 `/api/schema`。API 返回结构指纹与 API 契约版本的组合值。
4. App 每 60 秒最多检查一次服务端指纹；版本变化时原子清理当前用户的响应缓存，再读取服务端最新记录。检查失败或服务端尚未升级时继续使用现有缓存。
5. 更新版本记录并提交本地仓库。

## 边界

根目录 Docker Compose 部署 Go API，`DB_AUTO_MIGRATE=true` 会在服务启动时创建缺失表并补齐缺失列、索引。App 检测结构指纹变化后清理云端响应缓存并重新取数；它不会把远端表复制成手机 SQLite/IndexedDB 表。删除、改名、数据回填等破坏性迁移仍需要服务端单独编写迁移逻辑；新增 API 能力仍需发布相应客户端代码。
