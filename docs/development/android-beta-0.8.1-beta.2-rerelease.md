# Android 0.8.1-beta.2 重新发布

## 目标

撤销已发布但下载体验不稳定的 `0.8.1-beta.2`，在保持版本名不变的前提下使用新的 Android `versionCode 167` 重新发布。修复检查更新弹窗偶发消失、更新说明挤在一行、文字偏小及原生下载超时，并增加动态浏览器下载入口。

## 已确认原因

- 手机访问版本接口的首包时间偶尔超过旧客户端的 5 秒限制，超时异常又被静默忽略，因此手动检查弹窗会直接关闭。
- 原生下载器连接和读取超时较短，手机到更新站点的链路波动时会直接显示英文 `timeout`。
- 更新说明原先作为一个文本段落渲染，换行没有形成独立条目。
- 弹窗正文、说明、状态和按钮字号低于应用内其他弹层。

## 实施步骤

1. 将版本名统一回 `0.8.1-beta.2`，保留递增后的 `versionCode 167`。
2. 保留单请求控制并将检查超时增加到 30 秒，失败时显示明确提示。
3. 将更新说明按行渲染为列表，并统一放大弹窗字号。
4. 增大原生 APK 下载超时，增加短暂网络异常重试和中文错误提示。
5. 在更新弹窗加入“如下载失败，请到下载更新”的动态链接；链接使用版本接口当次返回的 `apkUrl`，不写死具体版本。
6. 合并版本记录中的 beta.3 内容到 beta.2，完成本地提交后推送源码和同名发布标签。
7. 等待 GitHub Actions 重新生成 APK，确认 `versionCode 167`、版本接口和动态下载地址，再用旧版手机完成检测、浏览器后路及安装验证。

## 发布约束

- 不纳入本地构建目录、旧 APK、纯 KT 源码或 Docker 归档。
- Release 说明不写源码托管平台整合和“一屏五项”。
- 同名重发依靠更高的 `versionCode` 区分旧包，避免安装过旧 beta.2 的设备无法升级。

## 本地检查

- 前端 TypeScript 检查通过。
- Android `compileKtwebDebugJavaWithJavac` 编译通过，确认动态浏览器入口和下载重试代码可编译。

## 修改分类

修复 / PATCH。已有检查更新、下载和更新弹窗未按预期稳定工作，本次恢复其稳定性与可读性，并为同一更新任务增加失败后路，没有新增独立业务任务。
