# 纯 Kotlin 资产模块开发与验收

## 目标

对照 Web 资产页 `app/src/app/app/(tabs)/assets/page.tsx`，在 Compose 原生版补齐资产与负债总览、配置分布、储蓄/贷款关联明细，以及资产新增、编辑和删除。资产数据按当前模式隔离：本地写入独立 SQLite 账本；云端以服务端成功响应为准，再更新云端缓存和页面状态。

## Web 数据和统计口径

资产实体来自 `app/src/lib/stark/models/types.ts`：

- `id/userId/accountId/name/type/balance/currency/createdAt/updatedAt`
- `type` 为 `CASH`、`BANK_CARD`、`ALIPAY`、`WECHAT`、`INVESTMENT`、`OTHER`。
- 余额可以为正或负：正数计入资产，负数作为其他负债展示；零余额不应形成资产配置。

Web 资产页的关联统计规则：

1. 资产总额 = 正余额资产 + 储蓄目标 `currentAmount` 总和。
2. 负债总额 = 负余额资产的绝对值 + 状态不是 `PAID_OFF` 的贷款剩余本金。
3. 净资产 = 资产总额 - 负债总额；负债率 = 负债总额 / 资产总额，资产为零但负债大于零时显示 100%。
4. 流动资产仅汇总现金、银行卡、支付宝和微信的正余额；集中度按最大单个正资产或储蓄总额除以资产总额计算。
5. 配置环图按资产类型汇总正余额，并将储蓄计划总额作为“储蓄计划”一类；负债不进入资产配置比例。
6. 明细区展示正资产、储蓄合计、负余额资产及未结清贷款。储蓄和贷款在此只读关联，不在资产表中复制一份。

Web 资产编辑表单允许输入正负非零余额；货币默认 `CNY`，资产类型可选上述六种。资产新增入口原本复用全局记账面板；原生资产页将提供直接可达的“新增资产”入口，并保留全局入口兼容。

## 原生实现步骤

1. 扩充资产模型和 JSON 编解码，完整保留 Web 字段；旧缓存缺少字段时安全补默认值。
2. 在 `NativeEntityDatabase` 仓库层加入按 `LOCAL` / `CLOUD` 与账本 ID 隔离的资产读取、整体缓存、单项保存和删除。
3. 增加资产 GET、POST upsert、DELETE API；云端请求失败时不先修改页面或缓存。
4. 以 Web 的统计口径实现净资产驾驶舱、资产/负债对比条、流动性/负债率/集中度指标和类型环图。
5. 明细区按正资产、负余额资产、储蓄和未结清贷款分组；编辑/删除只作用于资产实体，储蓄和贷款跳转到各自页面。
6. 增加新增/编辑表单，校验名称、余额和类型；允许负值并说明负余额会归类为负债；删除需二次确认，失败保留页面和数据。
7. 保存、删除和云端刷新后同步资产页及首页共享统计；保持本地数据、云端缓存和服务器数据彼此隔离。
8. 新增能力采用 `0.7.0-dev.1`，`versionCode` 递增到 `10009`；构建独立调试副本 APK，真机验收本地增改删、正负余额分类、汇总刷新和已有账单/储蓄/贷款数据不被覆盖。
9. 更新完整开发清单和变更记录，检查 `git diff --check`，只将资产源码、文档和版本文件提交到本地 Git，不推送 GitHub。

## 当前基线与限制

- Web 云端和本地仓库均提供资产列表、保存和删除；Go API 使用 `/api/assets` 账户实体路由。原生现已加入本地/云端隔离存储、资产分析卡片和 CRUD。
- 真机本地验收通过新增 `¥200` 资产、编辑为 `-¥50` 负债、校验资产/负债/净资产和首页数值联动、确认删除后恢复原账本余额。测试资产已删除；原有 4 笔消费账单仍保持不变。
- 当前调试副本未连接云端账户，因此云端资产写入仍待云端登录后验收。资产为空时为兼容现有原生本地账本，资产总额沿用账本余额作为展示回退值；存在资产实体后按 Web 口径汇总正负余额、储蓄和贷款。
- 手机继续使用原生调试副本 `com.wotty.stark.nativeapp.dev`，版本 `0.7.0-dev.1` / `versionCode 10009`；正式包未覆盖。
