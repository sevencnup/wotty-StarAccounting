# 前端加载与页面切换性能优化开发文档

## 目标

- 降低云端账本在首页、消费和贷款页面加载时传输与处理无关历史账单的开销。
- 减少页面切换时重复创建远端数据仓库、重复请求与图表初始化造成的卡顿。
- 保持账户隔离、账单刷新机制和既有页面数据结果不变。

## 优化策略

1. 为交易 API 增加仅返回可用月份的轻量接口；前端不再通过分页读取全部账单来生成月份选择器。
2. 云端按月/按年读取交易时复用已有分页交易接口，只请求所需月份；同一账本和月份的并发请求共享结果，并在账单写入后失效。
3. 让所有 `DataModeManager` 实例共享本地与云端仓库，避免页面切换时丢失短期缓存和重复网络请求。
4. 仅在图表进入视口附近后再加载 ECharts，并复用全局图表模块加载任务；底部导航明确预取目标路由代码。
5. 不启用 Next.js Cache Components：账本数据依赖浏览器令牌和当前账户，仍由客户端仓库请求，以避免错误缓存用户数据。

## 验收标准

- 首页、消费和贷款页不再为月份列表拉取完整交易流水。
- 按年只请求该年的 12 个月交易，按月只请求该月；相同请求不会并发重复发送。
- 账单保存、导入或删除后，相关月份与交易缓存会立即失效。
- 首屏与切换页面不会同步初始化视口外的 ECharts 图表。
- 后端测试、前端类型检查、前端测试与生产构建均通过。
