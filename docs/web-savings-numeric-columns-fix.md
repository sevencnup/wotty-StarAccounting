# 储蓄页面数字列异常修复开发文档

## 目标

修复储蓄页面将历史 `expenses` 数组下标（如 `1`～`106`）误显示为支出列的问题，并避免异常数字列继续通过本地草稿或计划配置恢复。

## 实施步骤

- [x] 梳理储蓄计划、计划配置和本地草稿的列名恢复路径。
- [x] 将数组格式的 `expenses` 视为旧数据格式，避免数组下标成为列名。
- [x] 过滤历史数组下标型数字列，同时保留正常的文字支出列。
- [x] 补充回归测试，覆盖数组和数字 key 两种异常数据。
- [x] 运行类型检查、测试和生产构建。
- [x] 更新版本记录并完成本地 Git 提交。

## 验收标准

1. 储蓄页面不再显示由数组下标产生的 `0`～`106` 数字列。
2. 历史 `expenses` 为数组或数字 key 对象时，页面仍能正常加载。
3. 正常的文字支出列、上月结余列和储蓄金额计算不受影响。
4. 本地草稿与计划配置中的异常数字列不会再次恢复到页面。
