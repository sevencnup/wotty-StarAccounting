# 储蓄目标编辑加载回归修复

## 问题

打开已有储蓄目标的编辑页面时，表单显示默认目标名称、空目标信息和全年 12 个月，而不是该目标真正保存的内容与月份。

## 判断

这不是单独的月份排序问题。目标名称与金额也未回填，说明编辑页面在目标定位、账户数据源或编辑初始化阶段回退成了新建状态。

## 实施步骤

- [x] 用现有目标 ID 和真实存储数据复现编辑加载失败。
- [x] 检查路由参数、当前账户、数据模式与目标查询的完整传递链路。
- [x] 建立“指定已有目标必须回填目标及实际月份”的回归测试。
- [x] 修复编辑初始化，禁止指定目标 ID 时短暂或永久显示新建目标数据。
- [x] 编辑路由等待 URL 参数解析后再挂载表单，并在目标 ID 变化时重新初始化编辑器。
- [x] 云端储蓄目标与计划改用轻量专用接口，避免为一次编辑下载完整账本。
- [x] 验证真实目标、自动化测试、类型检查和生产构建。
- [x] 更新应用版本并完成本地 Git 提交。

## 验收标准

1. 指定目标 ID 打开编辑页时，目标名称、金额、截止日期均来自该目标。
2. 编辑页只显示该计划保存的月份，不自动补齐全年 12 个月。
3. 目标加载期间不展示可编辑的默认全年表格。
4. 新建储蓄目标仍按默认月份初始化，不受编辑逻辑影响。

## 验证记录

- 目标 `05c6e22f-bc85-440d-9a0d-4ccab7d5ab70` 的真实配置与计划均为 2026 年 9–12 月。
- 全量同步接口约 8.3 MB、实测约 672 ms；储蓄目标专用接口约 903 B、实测约 9 ms。
- 无界面浏览器打开真实编辑链接后，目标标题、截止日期和 9–12 月均正确回填。
- Web 自动化测试 96 项通过，类型检查和生产构建通过。
