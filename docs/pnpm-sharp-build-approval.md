# pnpm Sharp 构建授权开发文档

## 问题

在仓库根目录执行 `pnpm dev` 时，pnpm 的依赖状态检查会调用安装流程。工作区中 `sharp` 的构建授权配置不是布尔值，导致构建脚本被忽略并使启动命令退出。

## 目标

为 `sharp` 明确授权执行其安装构建脚本，并提供根目录启动脚本，使根目录的 `pnpm dev` 能启动开发服务。

## 实施步骤

- [x] 定位 `pnpm-workspace.yaml` 中无效的 `sharp` 构建授权值。
- [x] 将授权值设置为布尔值 `true`。
- [x] 补齐根目录项目清单和开发启动脚本。
- [x] 在 Linux 上通过 `sh` 调用 Android Unix Gradle 包装器，避免错误执行根目录的 Windows 批处理文件。
- [x] 运行依赖安装和类型检查验证。
- [ ] 在配置 Java 运行环境后完成开发启动验证。
- [x] 补齐首页任务来源类型，恢复类型检查。
- [ ] 更新版本记录并完成本地 Git 提交。

## 验收标准

1. `pnpm install` 不再报告 `sharp` 的构建脚本被忽略。
2. 根目录的 `pnpm dev` 能越过 pnpm 依赖状态检查并启动子服务。
3. Web 类型检查通过。
