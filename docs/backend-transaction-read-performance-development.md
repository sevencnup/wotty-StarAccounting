# 后端交易读取性能优化开发文档

## 目标

- 消除普通交易分页、对账、导出和账单归类读取时对 `/api/sync` 全量同步接口的依赖。
- 复用带 `(accountId, date)` 索引的交易分页接口，避免服务端为少量交易读取序列化整本账本的所有实体。
- 降低兼容同步接口内部的重复数据库查询，不改变写入协议和账户隔离规则。

## 现状

- `transaction` 已具备 `(accountId, date)` 联合索引；按账本和月份的分页查询可命中该索引。
- 前端的普通看板已改为按月接口，但 `getTransactions()`、`getTransaction()` 仍读取 `/api/sync`，后者会一次加载并序列化所有交易、资产、预算等同步实体。
- `/api/sync` 的读取路径对同一账本的储蓄目标执行了两次查询。

## 实施步骤

1. 云端仓库的交易分页、全量导出和单笔读取改用 `/api/transactions` 与 `/api/transactions/{id}`，保持大页请求自动分批完成的现有调用语义。
2. 删除不再使用的同步读取缓存；写入继续使用兼容的 `/api/sync` 协议。
3. 同步读取路径复用一次储蓄目标查询结果，避免重复 SQL。
4. 更新版本记录，执行后端测试、前端类型检查、前端测试和生产构建。

## 验收标准

- 常规交易读取不再向 `/api/sync` 发出 GET 请求。
- 对账每页最多请求 500 条交易；导出和归类会连续请求交易分页接口而非额外同步资产等实体。
- 原有分页、排序、账户权限和写入流程保持不变。
