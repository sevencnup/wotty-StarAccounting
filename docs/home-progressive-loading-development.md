# 首页渐进加载开发文档

## 目标

- 让首页在云端数据较多或网络较慢时优先呈现当前收支核心信息，而非等待所有模块数据完成。
- 将资产、预算、贷款、储蓄计划和历史趋势作为后续阶段加载，避免底部模块阻塞首屏。
- 对视口外的首页模块使用可见性触发渲染，减少首次 DOM 创建和计算压力。

## 实施步骤

1. 将首页数据读取拆分为核心账单阶段与补充财务数据阶段；核心阶段只读取当前统计周期及上个周期的账单和可用月份。
2. 核心阶段成功后立即显示首页头部和收支卡片；补充阶段并行读取资产、预算、贷款、储蓄目标及历史账单，并在数据到达后更新对应模块。
3. 页面按模块顺序逐级放行；只展示当前最靠前的未完成模块占位，后续模块即使数据先返回也要等待上方模块完成，避免内容插队和布局跳动。
4. 使用 `IntersectionObserver` 让底部建议与趋势模块接近视口后再挂载，保留占位骨架以避免页面布局跳动。
5. 更新版本记录，执行前端类型检查、测试和生产构建。

## 验收标准

- 首页不再等待资产、贷款、储蓄计划和历史趋势账单全部完成才展示核心收支。
- 首屏仅请求展示当前收支所需账单；补充历史账单在核心内容可见后读取。
- 模块严格从上往下出现，不会发生下方内容先显示、再向中间插入模块的情况。
- 账单或储蓄保存后的刷新、年份统计、月份可选状态与数据错误提示保持正确。
