# 首页贷款待办筛选修复开发文档

## 问题

贷款已经还清、待还本金为 `0` 时，首页“待还贷款”仍可能展示还款天数；同时首页把储蓄和贷款共用待办列表中的首项直接展示在贷款卡，造成储蓄截止天数被误标为待还贷款。

## 目标

首页只为实际仍有待还本金的贷款生成还款待办，并确保贷款卡只读取贷款来源的待办；状态已结清或待还本金不大于 `0` 的记录均不展示还款提醒。

## 实施步骤

- [x] 为首页汇总增加“零余额贷款不生成待办、储蓄待办不误入贷款卡”的回归测试。
- [x] 统一首页贷款待办与贷款页的进行中判定：非结清且待还本金大于 `0`。
- [x] 为通用待办标记来源，贷款卡仅读取贷款待办。
- [x] 运行单元测试、类型检查和生产构建。
- [ ] 更新版本记录并完成本地 Git 提交。

## 验收标准

1. 没有进行中贷款但存在储蓄截止日时，首页贷款卡显示“无待还”。
2. 剩余本金为 `0` 的贷款，即使历史状态仍为 `ACTIVE`，首页也不显示“X 天后”还款提醒。
3. 剩余本金大于 `0` 且未结清的贷款仍正常显示最近还款日。
4. `pnpm test`、`pnpm typecheck` 与 `pnpm build` 通过。
