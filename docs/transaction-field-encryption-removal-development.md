# 交易字段数据库加密移除开发文档

## 目标

- 移除交易商户名称和交易描述的 AES-GCM 加解密能力。
- API 对 `transaction.merchant`、`transaction.description` 直接读写明文，不再依赖 `DATA_ENCRYPTION_KEY`。
- 移除开发与 Compose 配置中的加密密钥说明，避免新部署继续配置已废弃的功能。
- 不修改现有数据库记录，也不自动清空任何用户数据。

## 实施步骤

1. 删除后端加密工具及其测试，移除数据库启动阶段的密文迁移和密文列类型兼容逻辑。
2. 将交易同步读取和写入改回直接使用数据库字段值。
3. 删除示例环境变量、Docker Compose 注入和数据库配置文档中的密钥配置。
4. 更新版本记录，并执行后端测试、前端类型检查和前端测试。

## 验收标准

- 后端不再读取或校验 `DATA_ENCRYPTION_KEY`。
- 交易 API 不会因历史 `enc:v1:` 内容的解密失败而返回 500。
- 新写入的商户名称与交易描述以明文保存。
- 现有密文不会被服务自动更改；数据清理由用户在确认后另行执行。
