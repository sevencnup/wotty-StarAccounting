# 账户设置、注册开关与密码找回开发文档

## 目标

- 登录页提供“记住密码”选项，但不得以明文形式写入普通浏览器存储。
- 设置页新增“账户设置”，将已登录用户的密码修改入口迁入其中。
- 管理员可关闭或开启新的账户注册；关闭后登录页不展示注册入口，后端也拒绝注册请求。
- 未登录用户可通过安全的身份验证流程找回密码。

## 当前实现与约束

- 当前密码修改接口 `POST /api/auth/password` 要求有效 JWT，因此只能供已登录用户使用。
- 服务器尚未配置邮件发送、短信发送或管理员授权规则。
- 当前用户记录包含 `role` 字段，但现有注册流程没有明确的管理员初始化与授权策略。
- 浏览器 `localStorage` 不适合保存明文密码；Web 端应优先依赖浏览器密码管理器，Android 端若需应用内记忆密码应使用系统安全存储。

## 实施步骤

1. 确认管理员授予规则，以及忘记密码时用于验证身份的渠道。
2. 后端增加持久化的注册开关和仅管理员可访问的查询/更新接口；注册接口在关闭时拒绝新账户。
3. 后端实现选定的密码找回验证流程，包含短时有效、一次性使用和限流保护。
4. 前端登录页增加安全的凭据记忆交互、注册开关状态读取与“忘记密码”入口。
5. 前端设置页增加“账户设置”入口，迁移已登录密码修改功能并添加管理员注册开关。
6. 补充前后端测试，完成类型检查、前端测试、生产构建和后端测试。
7. 更新版本记录。

## 待确认的安全决策

- 管理员如何确定：指定环境变量中的管理员邮箱，还是将首个注册用户设为管理员。
- 忘记密码如何验证身份：SMTP 邮箱验证码/链接、短信验证码，或管理员人工重置。
- “记住密码”是否仅记住邮箱并交由系统密码管理器保存密码，还是需要 Android 安全存储支持。

## 验收标准

- 关闭注册后，登录页不显示注册入口，直接调用注册 API 也被拒绝。
- 非管理员无法读取或修改注册开关。
- 忘记密码流程不泄露账户是否存在，令牌/验证码过期或使用后不可再次使用，并具备频率限制。
- 已登录用户仍可在账户设置中修改自己的密码。
- 凭据记忆不把明文密码保存到普通 Web 存储。
