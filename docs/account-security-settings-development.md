# 账户设置、注册开关与密码找回开发文档

## 目标

- 登录页提供“记住密码”选项，但不得以明文形式写入普通浏览器存储。
- 设置页新增“账户设置”，将已登录用户的密码修改入口迁入其中。
- 管理员可关闭或开启新的账户注册；关闭后登录页不展示注册入口，后端也拒绝注册请求。
- 未登录用户可通过安全的身份验证流程找回密码。

## 当前实现与约束

- 当前密码修改接口 `POST /api/auth/password` 要求有效 JWT，因此只能供已登录用户使用。
- 当前部署环境无法发送邮件或短信；密码恢复不能依赖邮件验证码或链接。
- 当前用户记录包含 `role` 字段，但现有注册流程没有明确的管理员初始化与授权策略。
- 浏览器 `localStorage` 不适合保存明文密码；Web 端应优先依赖浏览器密码管理器，Android 端若需应用内记忆密码应使用系统安全存储。

## 实施步骤

1. 使用仅部署者掌握的 `ACCOUNT_ADMIN_KEY` 作为管理员恢复密钥；密钥只从 API 进程环境变量读取，不能写入前端或数据库。
2. 后端增加持久化的注册开关和需要“已登录 + 管理员恢复密钥”的更新接口；注册接口在关闭时拒绝新账户。
3. 后端实现无邮件的密码恢复：验证邮箱、新密码与管理员恢复密钥，按邮箱限流，并且不泄露邮箱是否已注册。
4. 前端登录页增加安全的凭据记忆交互、注册开关状态读取与“忘记密码”入口。
5. 前端设置页增加“账户设置”入口，迁移已登录密码修改功能并添加管理员注册开关。
6. 补充前后端测试，完成类型检查、前端测试、生产构建和后端测试。
7. 更新版本记录。

## 已确认的安全决策

- 管理员授权和无邮件密码恢复统一使用 `ACCOUNT_ADMIN_KEY`。部署者应设置至少 16 位、随机且不会复用的值，并通过安全渠道提供给需要恢复账户的人。
- “记住密码”在界面中实现为“记住登录状态”：勾选时 JWT 存入 `localStorage`，未勾选时仅存入当前会话的 `sessionStorage`；应用不保存明文密码，浏览器/系统密码管理器可自行管理凭据。

## 验收标准

- 关闭注册后，登录页不显示注册入口，直接调用注册 API 也被拒绝。
- 没有管理员恢复密钥的人无法修改注册开关；密钥从不在 API 响应中返回。
- 忘记密码流程不泄露账户是否存在，并具备按邮箱的频率限制。
- 已登录用户仍可在账户设置中修改自己的密码。
- 凭据记忆不把明文密码保存到普通 Web 存储。
