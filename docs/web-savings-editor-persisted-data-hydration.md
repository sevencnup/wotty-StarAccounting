# 储蓄编辑页已保存数据回填修复开发文档

## 问题

储蓄总目标编辑页保存后再次打开，目标配置、月份、支出列与月度行内容显示为空。

## 根因

服务端把 JSON 字段 `planConfig` 与 `expenses` 当作 JSON 字符串再次序列化后写入数据库。接口返回的数据因此多了一层字符串包装；前端只解析一次，无法得到可用于回填的对象。

## 目标

1. 已存在的双层编码数据仍可正常回填。
2. 后续保存不再生成双层编码 JSON。
3. 保存失败不得被误报为保存成功或清理草稿。

## 实施步骤

- [x] 读取实际储蓄目标与计划接口响应，确认双层编码数据。
- [x] 为前端 JSON 对象解析增加旧数据兼容，并添加回归测试。
- [x] 修正服务端 JSON 原始字段的写入逻辑。
- [x] 让储蓄计划保存失败显式返回错误，保留草稿。
- [x] 运行 Web 测试、类型检查、生产构建及服务端测试。
- [x] 更新版本记录并完成本地 Git 提交。

## 验收标准

1. 现有目标 `05c6e22f-bc85-440d-9a0d-4ccab7d5ab70` 重新打开时能回填 2026 年 9–12 月及已保存支出。
2. 保存后重新打开，目标名称、月份、收入、计划储蓄和支出列都保留。
3. 服务端返回的新 `planConfig`、`expenses` 为普通 JSON 字符串，不含额外的一层 JSON 引号。
4. 任意一个目标或计划写入失败时，编辑页面展示失败提示，并保留草稿。
