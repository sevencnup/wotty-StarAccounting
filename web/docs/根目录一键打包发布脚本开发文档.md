# 根目录一键打包发布脚本开发文档

- 文档版本: `v1.3.3`
- 关联版本: `V2.3.139`
- 更新时间: `2026-04-10`

## 1. 需求背景

根目录一键发布脚本已经改成了“本地直传服务器”模式，但上一版仍然优先依赖：

1. 系统环境变量
2. 执行时交互输入

这会导致双击 `一键打包发布.bat` 后，如果当前终端环境里没有提前设置：

1. `wotty_DIRECT_HOST`
2. `wotty_DIRECT_USER`
3. `wotty_DIRECT_APP_DIR`

脚本就会停在 `SSH host:` 这一步，和 `sevencn.com` 那种“直接读本地配置文件后自动执行”的体验不一致。

## 2. 参考实现

参考 `sevencn.com` 的旧方案可以看到，它的行为是：

1. 根目录 `.bat` 不做交互式采集
2. `scripts/deploy.js` 启动时自动读取根目录 `.env`
3. 同时读取根目录 `deploy-config.json`
4. 用配置文件里的服务器地址、端口、用户名和上传目标直接执行部署

因此本次要把 `wotty-StarAccounting` 的一键脚本也补成同样的模式。

## 3. 本次改造目标

改造后优先级如下：

1. 命令行显式参数
2. 系统环境变量
3. 根目录 `.env`
4. 根目录 `.env.local`
5. 根目录 `deploy-config.json`
6. 最后才交互询问

这样在根目录配置好部署文件后，双击 `.bat` 就不会再停在 `SSH host:`。

## 4. 新增与更新产物

1. 更新根目录 `deploy-one-click.ps1`
2. 新增根目录 `deploy-config.json`
3. 更新根目录 `.env.example`
4. 更新根目录 `一键打包发布.bat`
5. 更新本文档到 `v1.3.3`

## 5. 配置约定

### 5.1 deploy-config.json

当前根目录新增：

`deploy-config.json`

默认结构：

1. `server.host`
2. `server.port`
3. `server.username`
4. `server.appDir`
5. `server.keyPath`
6. `process.serverName`
7. `process.webName`
8. `health.serverUrl`
9. `health.webUrl`

当前已按现有项目环境预填：

1. 主机：`103.69.128.25`
2. 端口：`22011`
3. 用户：`root`
4. 目录：`/www/wwwroot/staraccountting.sevencn.com`

### 5.2 .env / .env.local

脚本会自动读取根目录：

1. `.env`
2. `.env.local`

目前支持读取的部署变量：

1. `wotty_DIRECT_HOST`
2. `wotty_DIRECT_USER`
3. `wotty_DIRECT_PORT`
4. `wotty_DIRECT_APP_DIR`
5. `wotty_DIRECT_KEY_PATH`

### 5.3 默认行为

当 `deploy-config.json` 已存在且值完整时：

1. 不再询问 `SSH host`
2. 不再询问 `SSH username`
3. 不再询问远端目录
4. 直接进入本地构建、打包、上传和远端部署流程

## 6. 验收标准

## 7. 2026-04-10 稳定性补丁

### 7.1 本次问题现象

1. 服务器首页返回 `403 Forbidden`
2. `npm install --production` 在远程服务器失败，但发布脚本仍继续执行
3. PM2 重启阶段出现 `cd: server: No such file or directory`
4. 服务器实际运行的是 `Node v16.9.0`，不满足 Prisma 的最低要求 `>= 18.18`

### 7.2 本次加固内容

1. `scripts/deploy.js` 的远程脚本增加 `set -e`
2. 安装依赖前增加 Node.js 版本检查
3. PM2 启动入口改为绝对路径
4. 上传完成后校验 `web/index.html`
5. 自动修正 `web/` 目录权限为目录 `755`、文件 `644`

### 7.3 结论

本次 `403` 更像是服务器端发布链路不稳定叠加环境不满足要求造成的复合问题，不是本地 `web/out` 未生成。后续应先把服务器 Node.js 升级到 `18.18+`，再重新执行一键发布。

## 8. 2026-04-11 服务器恢复操作

### 8.1 推荐版本

1. 本项目至少需要 `Node.js >= 18.18`
2. 推荐直接升级到 `Node.js 20 LTS`
3. 升级完成后再执行根目录 `一键打包发布.bat`

### 8.2 手动恢复要点

1. 登录服务器先检查 `node -v`
2. 如果低于 `18.18`，先升级 Node
3. 检查 `/www/wwwroot/staraccountting.sevencn.com/web/index.html` 是否存在
4. 修正 `web/` 目录权限为目录 `755`、文件 `644`
5. 校验 `pm2 status` 中 `wotty-server` 是否为 `online`

### 8.3 文档指引

具体命令见 `docs/服务器Node升级与发布恢复指引.md`

## 9. 2026-04-11 SSH 非交互环境说明

### 9.1 问题现象

1. 手动登录服务器执行 `node -v` 已经是 `v20.x`
2. 但一键发布脚本通过 SSH 执行时仍打印 `v16.9.0`
3. 导致 Prisma 依赖安装被判定为不满足 `Node >= 18.18`

### 9.2 根因

这是因为 SSH 非交互 shell 与手动登录 shell 的 `PATH` 不一致，脚本命中了旧版 Node。

### 9.3 当前处理

`scripts/deploy.js` 已增加自动探测逻辑，会优先尝试满足要求的 Node 版本，并把对应路径临时加入当前远程会话的 `PATH`。
