# 2026-04-11 补齐静态导出缺失依赖并恢复干净发布

## 本次目标

解决 GitHub 干净工作树重新构建静态站点时，因缺少依赖、文档导航工具、动态路由静态参数与客户端组件边界声明，导致导出中断、服务器无法拿到修复后 `web/out` 产物的问题。

## 本次完成

1. 补齐静态导出构建依赖
   更新 `web/package.json` 与 `web/package-lock.json`，加入 `build:export`、`cross-env`、`@capacitor/core` 与 `@capacitor/cli`。
2. 补齐静态文档导航工具
   新增 `web/src/lib/document-navigation.ts`，恢复登录页、注册页、PWA 清理与系统栏同步所需的导航能力。
3. 修复动态总览路由导出
   更新 `web/src/app/(dashboard)/[dashboardEntry]/page.tsx`，补充 `generateStaticParams()`，让 `DefaultDashboard` 等主题总览在 `output: export` 下生成真实静态页面。
4. 修复客户端骨架边界
   更新 `web/src/app/(dashboard)/data/DataLoadingShell.tsx` 与 `web/src/features/assets/components/themes/AssetsLoadingShell.tsx`，显式声明客户端组件，避免导出预渲染阶段把客户端主题函数当成服务端调用。

## 验证

- `npm.cmd install`
- `npm.cmd run typecheck`
- `npm.cmd run build:export`
- 确认 `web/out/DefaultDashboard/index.html` 已生成
- 确认 `web/out/auth/login/index.html` 已生成
- 确认 `web/out/data/index.html` 已生成

## 结论

这次补齐后，GitHub 上的代码已经可以在干净工作树里独立完成静态导出，服务器重新发布时就能拿到完整的 `web/out` 目录，不会再因为发布机缺失本地未提交改动而把 `/DefaultDashboard/` 之类的路由继续留在 403 状态。
