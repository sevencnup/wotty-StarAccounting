# 2026-04-11 修复调试 APK 默认后端未注入导致登录请求回落前端

## 背景

- Android APK 登录页提交时调用的是相对地址 `/api/auth/login`。
- 原生 APK 只有在构建时写入 `NEXT_PUBLIC_NATIVE_DEFAULT_API_BASE_URL` 后，运行时才会把请求拼成真正的后端地址。
- 之前普通 `apk:debug` / `apk:release` 脚本没有把这个原生专用地址写进去，结果打包后的登录请求会直接回落到前端 `3000`，表现为 `POST /api/auth/login 404`。

## 本次处理

- 更新 `web/scripts/build-android-debug.ps1`
  - 调试 APK 构建时默认写入 `http://当前电脑局域网IP:3006`。
  - 若显式设置了 `NEXT_PUBLIC_NATIVE_DEFAULT_API_BASE_URL`，优先使用显式值。
- 更新 `web/scripts/build-android-release.ps1`
  - 正式 APK 构建时优先读取 `NEXT_PUBLIC_NATIVE_DEFAULT_API_BASE_URL`。
  - 若未设置原生专用地址，则自动继承 `NEXT_PUBLIC_API_BASE_URL`。
- 更新 `web/android/app/build.gradle`
  - Android 版本同步到 `2.3.148` / `23148`。

## 用户收益

- 调试 APK 现在默认直接走本机局域网 `3006`，不再误打到前端 `3000`。
- 正式 APK 的原生默认后端地址也不再漏配，后续切域名或切公网地址时更稳。
- Android 打包链路和联调壳的地址注入规则终于统一了。
