# 2026-04-11 修复 SSH 非交互环境误用旧版 Node 导致发布失败

## 本次目标

解决服务器已经升级到 Node 20，但根目录一键发布通过 SSH 执行时仍然拿到旧版 Node 16，导致 Prisma 安装被拦截的问题。

## 本次完成

1. 更新 `scripts/deploy.js`
   远程执行时自动扫描多个常见 Node 安装路径。
2. 更新 `scripts/deploy.js`
   自动选择满足 `Node >= 18.18` 的版本，并在当前远程会话中优先使用该版本。
3. 更新 `scripts/deploy.js`
   输出默认 PATH 命中的 Node 与最终使用的 Node / npm 信息，方便定位服务器环境差异。
4. 更新版本文档
   同步 `CHANGELOG.md`、`docs/根目录一键打包发布脚本开发文档.md`、`docs/服务器Node升级与发布恢复指引.md` 与 `docs/开发进度.md`。

## 结论

这次问题不是 Node 没升级成功，而是 SSH 非交互 shell 和手动登录 shell 使用了不同的 PATH，导致发布脚本仍命中旧版 Node。
