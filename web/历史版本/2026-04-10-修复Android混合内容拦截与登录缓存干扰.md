# 2026-04-10 修复 Android 混合内容拦截与登录缓存干扰

## 版本信息

- Android 版本：`2.3.133`
- 文档版本：`docs/React重构迁移开发文档.md -> v1.1.10`

## 问题现象

- APK 冷启动后未登录用户会卡在首页与登录页之间，表现为长时间停留不进入登录表单。
- 即使已经跳到登录页，提交登录时也会因为 `http://` 后端请求被 WebView 判定为 Mixed Content 而失败。

## 根因定位

- 真机 `adb logcat` 抓到旧缓存仍在触发 `https://localhost/auth/login?next=%2Fauth%2Flogin`，说明历史 Service Worker / Cache 还在干扰 APK 静态资源加载。
- 同一轮日志中抓到 Mixed Content 报错，确认 `https://localhost/auth/login.html` 下访问 `http://...:3006/api/auth/login` 被 Android WebView 拦截。

## 本次修复

- 调整 `web/capacitor.config.ts`:
  - Android 本地壳改为 `http` scheme。
  - 开启 `allowMixedContent`，兼容当前 HTTP 后端环境。
- 调整 `web/src/components/shared/PWARegister.tsx`:
  - 嵌入式运行时启动时主动注销残留 Service Worker。
  - 同步清理 Cache Storage，并仅执行一次受控刷新。
- 调整 `web/src/app/auth/login/page.tsx` 与 `web/src/app/auth/register/page.tsx`:
  - 登录/注册互跳改为文档导航锚点，避免 Next `Link` 预取继续碰到静态导出资源路径问题。

## 验证

- `npm.cmd run typecheck`
- `adb install -r` 安装新 APK
- `adb logcat` 复核登录跳转链路与 Mixed Content 报错

## 备注

- 当前方案优先保证 APK 能连通现有 HTTP 后端。
- 后续如果后端改成 HTTPS 域名，可再评估是否关闭 mixed content 兼容配置。
