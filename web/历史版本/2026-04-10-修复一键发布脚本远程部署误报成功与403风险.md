# 2026-04-10 修复一键发布脚本远程部署误报成功与 403 风险

## 本次目标

解决一键发布过程中“远程实际失败但脚本仍显示成功”的问题，并补强静态站点发布后的目录检查与权限修复，降低线上出现 `403 Forbidden` 的概率。

## 本次完成

1. 更新 `scripts/deploy.js`
   为远程部署脚本增加 `set -e`，让依赖安装、目录检查、权限修复和 PM2 启动任一步失败时立即退出。
2. 更新 `scripts/deploy.js`
   安装依赖前增加 Node.js 版本校验，服务器低于 `18.18` 时直接报错退出，避免 Prisma 安装阶段才失败。
3. 更新 `scripts/deploy.js`
   将 PM2 启动入口改为绝对路径，修复当前工作目录异常时的 `cd: server: No such file or directory`。
4. 更新 `scripts/deploy.js`
   上传完成后校验 `web/index.html` 是否存在，并统一修正 `web/` 目录权限为目录 `755`、文件 `644`。
5. 更新 `docs/根目录一键打包发布脚本开发文档.md`
   同步记录新的部署约束与验收标准。

## 结论

本次报错不是本地前端没打包出来，而是服务器环境和发布脚本同时存在问题：

1. 服务器 Node.js 仍是 `v16.9.0`
2. Prisma 依赖要求 `Node >= 18.18`
3. 旧脚本没有在远程失败时中断
4. 静态站点目录还存在权限导致 `403` 的风险
